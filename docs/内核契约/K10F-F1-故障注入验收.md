# K10F F1 故障注入验收

## 当前结论

F1 已通过本节点列明的十类软件故障注入门禁。Debug/Release 均为 209/209，F1A/F1B 共 8 个矩阵用例连续 20 轮、160 次执行全部通过；纯生产构建、警告错误与架构扫描通过。详细数字与日志见 F1B 记录。

本文件按收口规划的十类故障整理实际证据，不将正常重启、返回错误注入或 CTest 全绿视为完整 K10F 认证。F2–F5 尚未完成，不能宣布 Kernel 1.0 Frozen。

## 规划项目与证据

| 必需故障类别 | 当前证据 | 失败语义 |
| --- | --- | --- |
| Journal write | F1A 的 begin/INSERT/readback/commit 矩阵，F1B 的两阶段摘要 | 失败不安装对象/Revision，原 Journal 不变 |
| Snapshot write | F1B 发布/索引/复用 read/hash 矩阵，close 元数据矩阵 | 保留原索引；孤立文件允许，伪成功 Detached 禁止 |
| Hash | F1B 的 Journal/outcome/Snapshot/Workflow 摘要，E2A Asset 摘要故障 | 摘要错误或异常不生成被承认的部分材料 |
| SQLite transaction | F1A 的 begin/execute/commit 和 rollback 自身错误/异常 | 普通失败回滚；无法确认 rollback 则撤销 Ready、隔离连接、新实例恢复 |
| Task accept | F1A 的真实 Command→Task 持久接受失败，F1B Executor 返回错误/异常 | 准备态无残留；已持久接受后 Executor 拒绝则终态 Failed，不滞留 Running |
| Workflow checkpoint | 原执行前 checkpoint 拒绝 handler 用例；F1B 执行后六阶段矩阵 | 执行前不跑，执行后补 checkpoint 或复用原幂等结果 |
| History persistence | F1A 普通写/Undo/Redo 矩阵与重启游标断言 | History 与 Document/Revision/Journal 不分裂，不跨失败提交推进 cursor |
| Asset publish | filesystem_asset_store_tests 的目标冲突、Hash 故障、发布后验证失败与孤立复用 | 无覆盖、错误不返回可用引用，后续引用准入仍验证内容 |
| Event delivery | EventBus 抛异常/重入用例；Command 提交后订阅者失败 | 记录订阅者错误，仍交付其他订阅者，不逆转已提交 Command |
| Log / Trace exporter | Command 提交后日志失败、LocalTraceService exporter 失败、Task exporter 异常用例 | 诊断可见，已完成提交/任务结果不因观测失败而被改写 |

主要源证据位于 `tests/unit/runtime/history_runtime_tests.cpp`、`persistence_service_tests.cpp`、`task_runtime_tests.cpp`、`observability_tests.cpp`，以及 `tests/unit/kernel/event_bus_tests.cpp`、`command_query_runtime_tests.cpp` 和 `tests/unit/infrastructure/filesystem_asset_store_tests.cpp`。

F1A/F1B 的 100 个明确矩阵场景是本轮新增证据，不取代之前的 Asset/Event/Log/Trace 故障测试。测试专用注入端口不进入生产构建，也没有给 Host 添加测试后门。

## 边界

- 故障点是接口调用边界的返回错误/异常，或文件已发布但上层收到失败；没有据此认证真实存储设备掉电行为。
- 数据库已经提交但响应丢失、进程在真实执行中被终止，以及跨执行链的一致性需要 F2 独立进程测试；本节点不宣称覆盖全部机器指令级崩溃点。
- 并发交错和耐久压力由 F3 负责，性能/内存与 ASan 门禁分别由 F4/F5 负责。
- Kernel 不执行 Machine-specific safety 判断；不包含控制器、运动、激光或上层模块实现和物理机器认证。
