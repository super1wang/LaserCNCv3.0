# K10E E1B2 对象版本持久化与事务迁移

## 状态与范围

本节点闭合对象精确版本在事务、Journal、Snapshot、幂等回执与 History 中的保真链路，是 K10E 的内部本地提交节点，不代表 K10E 验收或 Kernel 1.0 Frozen。

仅涉及内核、持久化基础设施契约与测试；未引入业务模型或第三方几何类型。

## 对象身份与迁移

`ObjectRecord` 增加 `schemaVersion`（`foundation::Version`），默认 `1.0.0` 仅用于现有三字段构造的源码兼容。新持久化记录必须明确携带版本，不能依赖此默认值解码。

`ApplicationTransaction::migrateObject(id, targetVersion)` 使用由内核注入的 ObjectTypeRegistry，执行已注册的完整迁移路径。每一步仍验证源/目标数据；失败会污染事务，后续 Commit 拒绝。暂存结果在 Commit 前不可见，Rollback 不改变 Document 或 Revision。

普通 `replaceObjectData` 不改变版本。完整记录替换是私有能力，仅供显式迁移与 History 恢复使用，禁止调用方通过普通更新直接替换类型/版本。既有同事务删除再创建相同 ObjectId 的拒绝规则保持不变。

History 的 Updated 变化恢复完整 ObjectRecord，而不只恢复 Value，因此迁移的 Undo/Redo 同时恢复数据与精确版本。Undo 是已记录状态恢复，不会执行反向 Migration 或猜测降级规则。对象类型仍不可变。

## 持久化兼容矩阵

| 容器 | 新写入版本 | 可读取旧版本 | 对象格式 |
|---|---:|---|---|
| `lasercnc.state-journal` | 3 | 1、2 | 新版为 id/type/data/schemaVersion；旧版固定 id/type/data |
| `lasercnc.document-snapshot` | 2 | 1 | 同上 |
| `lasercnc.command-outcome` | 2 | 1 | 内嵌 Commit 的对象使用同一规则 |

三个载体统一使用内部 ObjectRecord codec。新版强制精确四字段；版本强制 major/minor/patch 三个非负 uint32 整数。缺字段、额外字段、字符串数字、负数、溢出均拒绝。

旧版严格三字段对象固定映射到 `1.0.0`，不是“选择当前版本”。新格式移除 schemaVersion 后仍保留新容器版本会失败；仅修改容器为旧版但保留新对象字段也失败。不支持识别被攻击者完整改写为合法旧文件的伪造来源；内容摘要是完整性校验而非身份认证。

## 验证

- Debug 全量 179/179 CTest 通过。
- 新增 6 个用例重复 20 次，共 120 项通过。
- 验证版本精确编解码、异常版本拒绝、显式迁移回滚、Journal/Snapshot/幂等回放保真、跨两次重启的迁移 Undo/Redo、重算摘要后仍拒绝畸形记录；既有旧 Journal v1 的 UndoBarrier 兼容测试继续通过。
- 架构扫描通过：65 个公共头文件、127 个生产源文件。
- Release 全量 179/179 CTest 通过；警告视为错误的 Debug/Release 构建通过。

## 尚未闭合

当前普通对象创建/替换的类型、数据与引用准入仍待接入事务最终候选状态；Document attach/open/recovery 的类型准入也未完成。本节点不据此承诺未知类型、合法编码但未注册版本、悬空引用或 Transient 持久化已经被全面阻止。

下一节点在模块注册之后、initialize/start 之前验证恢复状态，并把同一类型/引用准入规则接入事务 Commit 和 Document attach/open。之后继续 AssetRef/AssetStore、OCCT 规则与 K10F 可靠性认证。
