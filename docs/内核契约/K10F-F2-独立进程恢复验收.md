# K10F F2 独立进程恢复验收

## 当前状态

F2 已通过收口规划列明的七类独立进程恢复验收。当前版本 27 个三进程场景和 2 个早期二进程回归各重复 20 次，共 580 次测试、1,700 个子进程全部通过；Debug/Release 全集均为 238/238，纯生产与架构门禁通过。F2 只证明列明的软件退出边界，不能替代完整 K10F、ASan、性能或物理机器认证。

## 规划到证据的映射

| 收口规划项目 | 直接进程证据 | 关键组合状态 |
| --- | --- | --- |
| Command crash | F2A handler-staged、outcome-written、command-returned；F2B/F2C 的真实执行路径 | 未提交 claim abandoned，已提交回执 replay；不因恢复重复提交 |
| Transaction crash | F2A Journal INSERT、commit 前/成功后内存安装前；F2C 带 AssetRef 的提交边界 | Document/Revision/Journal/History 全部在同一提交侧，不出现部分安装 |
| Task crash | F2B 真实 BS worker 的 Running handler | Failed / Task.InterruptedByRestart，无活动线程任务；原 Command 只重放 TaskId 接受回执 |
| Workflow crash | F2B 真实 DocumentWrite 步骤提交前/后、两类不安全外部步骤 | Running checkpoint → Waiting 原 attempt；显式续行复用回执或拒绝不安全执行；再次重启保留原因链 |
| History crash | F2A Undo/Redo Journal 写入后和 commit 成功后；F2C 资产引用 Undo/Redo | cursor/extent、Revision、对象材料一致，保留的 redo 实际可用 |
| Asset publish crash | F2C 发布前、临时文件 flush 后改名前、真实改名后、引用提交前后 | 孤立文件允许；临时文件不被认作正式资产；丢失或损坏的已提交引用拒绝安装 |
| External effect crash | F2B 四类 ReplayPolicy 的实际 Publish 测试 handler；Never/ReconcileOnly 的 Workflow 交叉场景 | 启动只转为 Interrupted/Indeterminate/ReconcileRequired；独立调用记录证明无自动外部执行 |

详见 [F2A](K10F-F2A-命令事务与历史崩溃恢复.md)、[F2B](K10F-F2B-任务工作流与外部副作用崩溃恢复.md)、[F2C](K10F-F2C-资产发布中断与引用恢复.md)。类别存在交叉，不能把表中重复映射再累加为场景数。

## 测试规模与边界

F2A 10 个、F2B 9 个、F2C 8 个，共 27 个三进程场景；另保留早期 Persistence/Workflow 两个二进程恢复回归。新的三进程场景同时要求专用退出码和精确退出点标记，恢复和再次审计必须运行在新进程中，不以正常析构重建代替。

所有新场景使用真实 SQLite 和文件 Snapshot；Task 使用真实线程池；Asset 改名探针编译同一生产源文件并调用真实 Windows API。测试专用代码不进入生产目标。

F2B 实测并修复 Workflow checkpoint 丢失 Error cause 的问题；再次审计保留中断原因。F2C 未发现需修改生产资产实现的问题，旧恢复脚本的任意路径递归清理已移除。

这里的“允许重试”仅指 Safe/Idempotent 的显式调用；不等同于外部设备已实现 exactly-once。Never/ReconcileOnly 的 unknown 状态不会通过自动对账、伪成功回执或新 attempt 被本测试路径消除。

## 验收证据

当前版本 Debug 全集 238/238（63.48 秒）、Release 全集 238/238（64.16 秒）；全部 29 个进程用例重复 20 轮通过（671.62 秒），失败、超时和 flaky 均为 0。Production-only Release 的 31 个工程没有测试/contract/Catch2 目标；公共 API 和实现边界扫描分别覆盖 69 个头文件、133 个生产源文件。

直接日志为 `build/k10f-f2c-debug-tests.log`、`build/k10f-f2c-release-tests.log`、`build/k10f-f2-repeat20.log` 和 `build/k10f-f2c-production-build.log`；逐轮数据库、Snapshot、资产与进程输出保留在忽略的构建目录。每轮专用目录不递归清理调用者路径。

本次将 F1/F2 及其内核缺陷修复作为可靠性阶段的重要节点提交本地并同步远端；这更新了此前仅计划在完整 K10F 后远端同步的节奏，不发布 Kernel 1.0 Frozen。

F2 通过后按规划进入 F3；F3 并发压力、F4 性能/内存、F5 最终工程门禁仍是 Frozen 的必要条件。本阶段不开展 CAD/CAM/Machine/Process、Qt、产品 CLI/RPC/AI 等上层模块。
