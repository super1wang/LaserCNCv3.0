# ST1C6b15 版本解析策略枚举准入

## 契约

`VersionResolution` 是 Command/Query 描述符发现与执行请求共同使用的公开解析策略，合法闭集只有 Exact、Compatible。C++ 调用者可以强制构造未声明枚举，因此 Registry 和 Runtime 不能把“既不是 Exact 也不是 Compatible”混同为正常但无匹配版本，更不能在 Trace/诊断中将其写成 compatible。

本节点固定以下行为：

| 入口 | 未知策略的错误 | 副作用边界 |
| --- | --- | --- |
| `CommandRegistry::descriptor` / Command 内部 resolve | `Command.InvalidVersionResolution`，Validation | 不进入 Registry 查找，不返回 descriptor |
| `QueryRegistry::descriptor` / Query 内部 resolve | `Query.InvalidVersionResolution`，Validation | 不进入 Registry 查找，不返回 descriptor |
| `CommandRequest.versionResolution` | 同 Command 错误 | handler、Schema、Capability、幂等、事务、持久 Effect 均不执行 |
| `QueryRequest.versionResolution` | 同 Query 错误 | handler、Schema、Capability 与文档结果读取均不执行 |

Runtime 仍按既有观察边界为被拒请求创建失败 Trace；其 `versionResolution` 属性必须为 `unknown`，不能伪报 Exact 或 Compatible。失败请求可能短暂取得并释放既有执行活动租约，这只服务关闭线性化，不授予业务执行或持久写权限。

## 正向解析与兼容

Exact 继续只命中完整相等 Version；Compatible 继续在相同 major、版本不低于请求的候选中选择最高 Version。名称缺失仍为 NotFound，合法策略下无匹配候选仍为 UnsupportedVersion，Deprecated 命中及响应中的 resolvedVersion/contractStatus 均不变。

这是非法输入错误语义和观察精确性的收紧。公共头、VersionResolution 底层类型与两个已声明数字、Command/Query DTO、`lasercnc.command-signature.v2`、外部 Effect 签名、持久格式和 SQLite 版本均未修改。未知策略不会进入签名或留下可重放记录，也不提供把非法旧值映射成 Compatible 的迁移。

## 精确边界

本节点不改变跨 major 规则，不增加版本字符串解析、范围表达式或协议协商，也不签核 Version/请求文本/Value 的统一尺寸预算、幂等终态保留和持久历史总量；这些继续归 C6b 后续、C6c/d 与 C7。

本节点只覆盖 Application Kernel 的 Command/Query，不增加工程包、CAD/CAM/Process/Machine、GUI、产品 CLI/RPC/AI 或设备模块。
