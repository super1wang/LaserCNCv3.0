# ST1C6b16 快照存储写入证明准入

## 契约

`ISnapshotStore::writeAtomically` 的成功结果不是无类型布尔值：只允许 Created、AlreadyPresent。PersistenceService 在建立 `snapshot_index` 可信索引前必须验证 disposition；未知值为基础设施契约违例，返回 `Persistence.InvalidSnapshotWriteDisposition` 并回滚数据库事务。

AlreadyPresent 表示物理载体并非由本次调用新建，因此不能只信任枚举。内核必须以同一 SnapshotId 读回，并与本次已序列化、已计算摘要的精确 payload 逐字节比较：读取失败包装为 `Persistence.SnapshotStoreVerificationFailed` 并保留 cause；内容不同返回 `Persistence.SnapshotStoreContentMismatch`。只有证明相同后才写入索引。Created 保持既有成功路径，不额外强制读回。

任何上述失败都不得提交 `snapshot_index`；适配器已写出的文件可作为孤立不可变材料保留，不尝试跨数据库/文件系统伪造原子删除。后续 latestSnapshot/recover 只看已提交索引，因此不会把孤立材料当作恢复锚点。

## 兼容与边界

合法 FilesystemSnapshotStore 已在返回 AlreadyPresent 前核验身份和内容，本节点只增加 Kernel 对端口实现的防御性验证。公共头、两个 disposition 数字、Snapshot payload、LCNCSN02 外层信封、数据库 schema 与 SQLite 版本均不变；错误适配器此前可能写入的错误索引不自动修复，启动读取仍按既有摘要/身份规则 fail-closed。

本节点不宣称 Created 已物理落盘，不提供跨数据库与文件系统事务，也不签核快照总量、单次读回成本、目录容量或断电保证；输入预算归 C6c，容量测量归 C7，存储环境支持仍按 C5/ST1D。

本节点只触及 Application Kernel 持久边界，不增加工程包、CAD/CAM/Process/Machine、GUI、产品 CLI/RPC/AI 或设备模块。
