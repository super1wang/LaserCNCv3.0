# ST1C6b12 观察出口快照无分配发布

## 契约

Trace、Metrics 与 Diagnostics 在发布完成记录、聚合或 latest 报告时，只在所属服务锁内冻结当时的 exporter 数量，不再复制完整 `vector<shared_ptr<Exporter>>`。出口注册表只有追加、没有移除；通知阶段按冻结数量逐项在锁内复制一个 `shared_ptr`，随即锁外调用 exporter。因此发布点本身不再引入随 exporter 数量增长的快照分配，同时仍保持发布时的成员边界：该点之后追加或重入注册的 exporter 不参加本批通知。

逐项取得共享所有者仅保护当前 exporter 的调用寿命，不能把用户实现带回服务锁。exporter 返回 Error、抛异常以及失败记录资源不足仍按 [C6b11](ST1C6b11-观察出口失败记录资源隔离.md) 逐项隔离；一个出口失败不改变冻结数量内后续出口的通知机会。Diagnostics 的同 ID 执行租约保持到 latest 与 exporter 数量一同发布，随后在出口调用前释放；不同 ID 并行和同 ID 递归规则不变。

## 资源失败原子性

- Trace：首次完成若已进入有界完成窗口，冻结数量内的 exporter 都获得一次通知机会，活动身份已释放；发布完成记录以前的分配失败仍允许没有完成记录，但不得留下 active 身份。
- Metrics：若新聚合尚未插入，前置资源失败保持无聚合、无出口；一旦聚合已发布，调用返回成功并通知冻结数量内全部 exporter。
- Diagnostics：若报告尚未写入 latest，前置资源失败可向调用方逸出；一旦 latest 已发布，调用返回成功报告并通知冻结数量内全部 exporter。

隔离进程逐一注入每个动态分配点。Release 修复前真实红灯分别命中 Trace 完成路径的出口向量复制和 Diagnostics latest 之后的出口向量复制；修复后穷举基线为 Trace 完成合法/非法/abandoned `10/30/27`、Metrics `9`、Diagnostics `2`，并核对两个 exporter 的调用次数。另有 3/3 成员边界回归，证明三服务在首个出口回调中追加的出口只进入下一批。Metrics 原实现的向量复制位于聚合提交前，红灯阶段保持了强预发布原子性；本节点将其一并改为统一的无向量复制发布协议。

## 精确边界

“无分配”只描述 exporter 快照发布机制：冻结 `size()` 与复制单个 `shared_ptr` 不建立动态容器。完成记录、Metric 键/标签、Diagnostic 报告、Error/cause、用户 exporter、自身锁实现及查询返回值仍可能分配；本节点不承诺任意 OOM 下 API 都为 `noexcept`。exporter 数量、内容字节、失败窗口容量、active Span、Metric series 和 Diagnostic check 的统一预算仍归 C6c/C7。

本节点不修改公共头、DTO、错误码、持久格式或依赖，不引入远程观测、GUI、CAD/CAM、设备及其他上层模块。
