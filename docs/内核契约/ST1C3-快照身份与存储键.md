# ST1C3 快照身份与存储键

## 范围和节点

本节点仅处理内核身份、快照持久化与文件发布。不新增上层模块，不把附件或外部审计中的建议自动作为实现指令。

| 子节点 | 必须验证的内容 | 当前状态 |
| --- | --- | --- |
| C3a | 自动关闭快照不拼接 DocumentId，不用墙钟或进程局部计数表达跨重启身份；中文、路径字符、长 ID、大小写文档可关闭并恢复；真实多进程验证 | 本地检查点通过：Debug 378/378、专项 8/8、新增 5 项各 3 次、纯生产/架构及 ASan 三轮进程验证 |
| C3b | 显式 SnapshotId 与 Windows 文件键的大小写、保留名、长度和字符边界；临时文件独占发布及碰撞；旧键兼容与认证 | 未开始 |
| C3c | 时钟回拨下最新快照选择、历史快照/Journals 单独来源身份域、故障后不覆盖与不误恢复；统一 C3 回归 | 未开始 |

C3a 不改变 StrongId 的既有字节身份定义，不替所有 StrongId 引入全局长度或 Unicode 规范化策略。统一输入预算归 C6。不得因为自动生成键变安全而声称手工 SnapshotId 的文件别名问题已解决。

## 已核实的起点

基线 `b010777` 的 `DocumentRuntime` 将 `snapshot.close.`、DocumentId、system_clock 纳秒和进程静态计数组合为 SnapshotId。文件实现只接受长度不超过 128 的部分字符，再直接拼 `.snapshot`。因此合法 DocumentId 可以在关闭阶段失败；两层的身份域不同。文件检查使用 locale 字符分类，大小写键在 Windows 上可能映射同一路径。

`snapshot_index.storage_key` 当前必须等于 SnapshotId，负载包含精确 snapshotId/projectId/documentId 并校验摘要和修订。C3a 保留此格式以及旧文件读取，不批量改名、不清空历史。C3b 必须单独确定新旧键并存和错误隔离方案。

此检查同时存在于 `snapshot_persistence.cpp` 的单文档读取与 `recovery.cpp` 的恢复解码；C3b 不能只修改其中一处。临时文件名的 PID/uptime/计数组合只用于 CREATE_NEW 临时文件，不能与本次替换的业务 SnapshotId 生成混淆。

## C3a 设计约束

自动关闭使用 `snapshot.close.v2.` 加 256 位随机量的小写十六进制，共 82 字节。每次调用生成，不含 DocumentId、时钟、PID 或可回绕计数。随机初始化或取值抛错、全零结果均返回结构化失败，不退回时间命名。随机量是碰撞概率控制，不是绝对唯一证明，也不是安全凭据；持久化的不可变身份/负载冲突校验仍是最终防线，禁止碰撞时覆盖旧文件。

生成器测试接缝仅在私有源目录，不提供 Host 注入随机结果的公开接口。真实进程重启试验验证当前支持工具链上的实际行为，不宣称穷举随机空间或模拟物理断电。墙钟不再参与身份生成，但索引的 created_at_ms 及其排序仍由 C3c 核验；本节点不会修改系统时间。

名称中的 `v2` 仅标识自动命名方案，不是 Snapshot 负载版本升级：负载仍写 version 3，原有 version 1/2/3 读取路径、数据库 schema 和 storage_key 等值规则均不变。每次 capture 的随机量只是标识，不新增权限或绕过生命周期治理。长 DocumentId 回归验证到 1024 字节，不等于承诺无限 ID、任意非法 UTF-8 或任意深度目录支持。

## 验收证据

旧实现的两项回归均失败（47.68 秒）：13 个 DocumentId 夹具中，中文、路径字符及 96/128/129/1024 字节长 ID 共 7 项关闭失败；另一项确认旧键包含 DocumentId 且不满足新格式。失败日志保留 `build/st1c3a-red-tests.log`。测试诊断三目表达式一度触发 Catch2 宏优先级编译错误，已添加括号，失败构建日志同样保留；这不是生产代码编译失败。

最终证据见 [C3a 交付](../阶段交付/2026-09-04-ST1C3a-自动关闭快照身份.md)：Debug 378/378、专项 8/8、新增 5 项各 3 次、纯生产和定向 ASan 3 轮进程验证全部通过。C3a 已通过本地检查点；C3b/c 尚未通过，最终三配置与冻结仍归 ST1D。
