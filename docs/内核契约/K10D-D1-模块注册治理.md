# K10D D1 模块注册治理契约

## 1. 阶段状态

K10D D1 已验收，K10D 整体仍在进行中。本切片只闭合 `ModuleRegistrar` 和模块贡献所有权审计；`ExecutionGateway`、Host 原始入口收紧属于 D2，尚不能视为完成。

本切片只修改 Application Kernel、自动化测试与中文文档，没有创建 CAD、CAM、Machine、Process、Collision、Qt GUI、产品 CLI/RPC 或 AI 模块。

## 2. 唯一注册入口

`IModule` 的组合回调固定为：

```cpp
Result<void> registerComponents(ModuleRegistrar& registrar);
```

Registrar 提供以下贡献入口：

- `registerService()`；
- `registerCommand()`、`registerReadOnlyCommand()`、`registerAsyncCommand()`、`registerExternalEffectCommand()`；
- `registerQuery()`；
- `registerTask()`；
- `registerWorkflow()`；
- `registerScript()`；
- `registerEvent()`；
- `registerCapability()`。

每次调用先按稳定名称检查当前模块 Descriptor。未声明身份返回 `Kernel.ModuleContributionUndeclared`，且不会触及底层 Registry。Registrar 会保留首次失败，因此模块即使忽略失败结果并返回成功，ModuleRuntime 仍会拒绝启动。

## 3. Descriptor 精确核验

`ModuleDescriptor` 现在完整声明：required/provided services、commands、queries、tasks、workflows、scripts、events、capabilities。

所有模块回调之前，ModuleRuntime 执行两类检查：

1. 同一模块不能重复声明同一贡献；
2. 不同模块不能声明同一稳定贡献名称的所有权。

Command 与 Query 可以由同一所有者注册多个版本；Descriptor 的名称表示所有权域，不用版本号把同一契约拆给多个模块。

回调结束后，按类别比较 Descriptor 与实际成功注册集合。缺失或额外贡献返回 `Kernel.ModuleContributionDeclarationMismatch`；跨模块所有权冲突返回 `Kernel.ModuleContributionOwnerConflict`。

## 4. 失败回滚

Registrar 保存实际注册的 ServiceId、CommandKey、QueryKey、TaskName、WorkflowName 与 ScriptName。任何模块注册、initialize 或 start 失败时，ModuleRuntime 先按既有逆拓扑生命周期调用 stop/rollback，再逆向移除上述贡献。

Event 与 Capability 当前没有独立定义 Registry；`registerEvent()` 与 `registerCapability()` 只建立显式审计事实，不伪造运行态对象。未来若引入相应 Registry，必须继续由 Registrar 管理。

## 5. 自动化证据

Debug 与 Release 均为 165/165 CTest 通过；Production-only Release 构建通过，31 个工程中测试/contract/Catch2 目标为 0；架构扫描通过 63 个公共头文件与 122 个生产源文件。新增测试覆盖：

- 八类贡献全部声明并全部注册；
- 已声明但漏注册；
- 未声明注册且模块故意忽略错误；
- 跨模块稳定名称所有权冲突在回调前失败；
- 后续模块 start 失败时，六类实际 Registry 贡献与 Service 全部回滚；
- 既有依赖 DAG、确定性生命周期、异常转换与服务回滚测试继续通过。

重复稳定性与 D2 的最终证据将在 K10D 整体交付文档统一记录。

## 6. 未完成边界

AppKernel 当前仍保留原有 Registry/Runtime 访问器，以维持 D2 迁移期间的既有测试与调用点。因此本阶段只能声明“模块内部注册治理已闭合”，不能声明“Host 已无法旁路执行”。下一切片严格实现 ExecutionGateway、迁移 Host 调用并关闭原始可变入口。
