# K10E E3 几何域与应用状态边界

## 冻结的边界

本节点只固定未来接入规则，不下载或链接 OCCT/OCAF/XDE，也不建立 Geometry、CAD 或 CAM 模块。

Kernel Document 是唯一 Application Source of Truth，拥有稳定 ObjectId、Revision、应用元数据、依赖关系和 AssetRef。未来 `TDocStd_Document`、OCAF、XCAF 只能作为 Geometry Domain 的内部实现材料，不能与 Kernel Document 成为平级应用状态源。

`TopoDS_Shape`、`TDF_Label`、`TDocStd_Document` 和 `Handle(TDocStd_Document)` 不得进入 Kernel 公共头文件。未来 Geometry Adapter 可以把领域内容发布成不可变资产；跨边界只传稳定身份、内核值与 AssetRef，不传第三方句柄、可变对象或内部生命周期引用。

唯一用户级 Commit、Undo、Redo、Recovery 由 Kernel Transaction/History/Persistence 决定。OCAF Transaction/Undo 只可作为 Adapter 内部 staging：构建候选 → 发布不可变资产 → Kernel Command/Transaction 提交引用。内部失败不得提前改变应用状态；Kernel 提交失败可留下孤立资产，不得让 OCAF 自行推进第二套用户历史。

长计算仍必须进入 TaskRuntime/Scheduler；可靠多步编排仍经 Workflow。以上是未来模块接入约束，不代表本阶段已实现几何适配或领域补偿。

## 自动门禁

`VerifyKernelBoundaries.cmake` 的公共头文件禁用词加入 `TDF_` 与 `TDocStd_`，保留既有 `TopoDS_` 等第三方边界。`architecture.occt_boundary_negative_probes` 在独立构建目录生成四种典型泄漏样例，逐个调用真实扫描脚本，要求以禁止类型错误拒绝。

该门禁证明已知类型名称泄漏会被检测，不是 C++ ABI 分析器，也不声称识别任意别名或类型擦除。后续第三方接入仍须审阅实际 API、所有权与生命周期，并扩充负例。
