# K10E E1B3 对象状态准入闭环

## 节点结论与范围

E1B3 将对象类型契约接入真实状态链：事务最终候选集合、Document attach/open、启动恢复与 History 恢复。结合 E1A、E1B1、E1B2，E1 的对象类型治理、精确版本、显式迁移与状态准入已形成闭环。

这是 K10E 内部节点；AssetRef/AssetStore 和 OCCT 边界、K10F 认证尚未完成，不能宣布 K10E 验收或 Kernel Frozen。未扩展任何上层模块。

## 准入规则

`ObjectTypeRegistry::validateRecord(record, persistent)` 强制匹配已注册 ObjectTypeId 与精确 schemaVersion，并执行对应 Validator。持久状态拒绝 `Transient`，不静默省略对象。

`validateObjects(records, persistent)` 还检查稳定对象身份不重复、按精确版本枚举的引用全部落在同一 Document 的最终候选对象集合内。禁止跨文档隐式寻找引用；需要其他文档数据的上层模型不能借此建立可变跨文档对象指针。

已注册的旧版本仍可读取和编辑，不会自动迁移；显式迁移只能走 `ApplicationTransaction::migrateObject`。因此模块升级必须保留项目和 History 所需旧版本的 Validator 与迁移路径，不得要求 Kernel 猜测旧 Value。

## 事务

类型、数据与引用校验在 Commit 的 Journal 写入、History 准备、Document 写锁之前完成。Validator/Reference Enumerator 可以重入只读快照；最终提交仍通过既有 Revision 冲突检测。

校验对象是完整暂存集合，而不是按逐次变更立即拒绝引用：同一事务允许先建立引用对象再建立目标，也允许同时移除引用者与目标。单独删除仍被引用的目标必须失败。

准入失败不会发布对象、推进 Revision、写 Journal、移动 History cursor 或投递 Domain Event。同步幂等的持久 claim 被释放；既有进程内失败结果缓存保持不变，同进程同键仍返回原失败，重启后无已完成持久结果的请求可重新尝试。

## Document 生命周期

attach 在设置 Opening、写持久目录或安装 Document 之前校验候选图。无效类型、版本、数据或重复对象身份不会留下生命周期条目或文档。

open 复用 attach 准入。关闭后的文档若持久材料含未注册版本，打开失败并保持内存/持久目录均为 Detached，不恢复为可查询或可写状态。

当前持久化策略以 AppKernel 的 PersistenceService 是否已配置为边界：配置持久化的 Kernel 内不允许持久 Document 携带 Transient 对象；纯内存内核可以接受 Transient。没有引入第二套临时文档持久化策略。

## 启动顺序

启动顺序改为：模块依赖和贡献声明校验 → 注册全部贡献 → 冻结 ObjectTypeRegistry → 初始化持久化并解析恢复材料 → 类型/引用准入 → 安装 Document/History/生命周期 → 模块 initialize/start → 其余运行时冻结与 Ready。

注册阶段只持有 ModuleRegistrar，没有活动 Document 写入能力。恢复材料在安装前验证，所有 initialize/start 都只能观察已准入状态。准入错误或异常走 ModuleRuntime 既有逆序回滚，已发布贡献会被移除，内核保持 Failed。

恢复对象集合检查类型、精确数据和完整引用图；历史 before/after 是分散的变更材料，只检查类型、精确数据与持久策略，不把单条历史变更误当成完整图。Undo/Redo 真正应用时再校验最终对象集合。

当前恢复扫描到的所有对象与 History 所需类型均要求已安装，即使对象已被删除或文档已关闭，也不能静默丢弃未知类型的历史材料。未来如需历史裁剪或选择性项目加载，应另立契约，不以忽略校验实现。

## 实现边界

AppKernel 始终向 TransactionManager 和 DocumentRuntime 注入受治理 ObjectTypeRegistry，Host 不获得这两个对象的可变状态存储。独立底层组件测试可不注入注册表，用于单独验证事务或持久化机制；这不是 AppKernel 的宽松模式。

原有 Command/Workflow/独立进程测试的合成对象类型均通过测试模块显式声明，不在生产代码增加通配类型或放行兜底。
