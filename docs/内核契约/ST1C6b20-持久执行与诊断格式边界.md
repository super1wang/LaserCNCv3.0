# ST1C6b20 持久执行与诊断格式边界

## 结论与范围

本节点完成 `PersistenceService` 中 Idempotency、ExternalEffect、Diagnostic、Recovery 与 Session DTO 的剩余逐项审计。源码与红测确认一个生产缺陷：`claimCommand()` 原先把后端返回的任意成功影响行数都当作幂等占位成功，因此 0 行或大于 1 行也可能向调用者返回 `Acquired`。现已要求首次占位必须恰好影响 1 行；否则回滚并返回 `Persistence.IdempotencyClaimWriteCountInvalid`，同一键可以在失败后重新尝试。

本节点只修改 Application Kernel 的持久化实现、内核测试和中文文档，不增加 CAD、CAM、Machine、Process、GUI、产品 CLI/RPC/AI 或其他上层模块。

## Idempotency 契约

`IdempotencyClaimDisposition` 的 Acquired/Replayed 与 `IdempotencyClaim`、`IdempotencyReplay` 都是持久组件产生的输出状态，不是调用者可写回数据库的状态机输入。`claimCommand(key, signature)` 的 `signature` 在 Persistence 层按精确 `Value` 序列化结果和 SHA-256 摘要绑定；正常 CommandRuntime 当前生成 `lasercnc.command-signature.v2`，但这不允许调用者绕过 CommandRuntime 获得 AppKernel 业务执行权。

- 新键占位的控制状态为 `pending`；Host 重启初始化会把遗留 `pending` 标为 `abandoned`；合法同签名重试可重新取得占位。
- `completed` 必须具有摘要有效的 outcome，并与同一 Journal Transaction 或 Task 记录交叉认证；缺失、错误身份或内容不一致均失败关闭。
- `lasercnc.command-outcome` 当前只写 v3，读取 v1/v2/v3。v1 对象记录为 `id/type/data`，v2 增加精确 schemaVersion，v3 再增加资产引用；本节点用摘要有效的 v1/v2 材料验证读取兼容，并保留 v3 正常写入/重放。
- 不支持的 outcome 版本即使摘要正确，也返回 `Persistence.InvalidIdempotencyPayload`，不会降级解释为其他版本。
- 首次 `INSERT command_idempotency` 必须恰好影响 1 行。0 行或 2 行均回滚，不能产生幽灵占位、成功回执或后续冲突。
- `releaseCommandClaim()` 是 pending/abandoned 的幂等清理：目标不存在、签名不符或已经 completed 时允许零行删除成功。该成功只表示无需再清理，不是命令完成、外部副作用完成或持久提交证明，因此不套用“恰好一行”的占位证明规则。

本节点不修改 `lasercnc.command-signature.v2`、command-outcome v3、state-journal v4、Task 格式或 SQLite schema。新错误码只收紧后端成功行数异常时的行为。

## ExternalEffect 契约

`ReplayPolicy` 是 `claimExternalEffect()` 的实际公共闭集输入，合法值为 Safe、Idempotent、ReconcileOnly、Never；其余底层值在锁、序列化和数据库写入前返回 `Persistence.InvalidExternalEffectPolicy`。`ExternalEffectClaimDisposition`、`ExternalEffectClaim`、`ExternalEffectRecord`、`ExternalEffectState` 与 `RecoveryDisposition` 是验证持久材料后产生的输出，不构成调用者写回状态的入口。

- Persistence 层精确保存 signature payload、摘要、策略、状态和可选 outcome；新占位及 complete/interrupt 更新均要求恰好一行。
- EffectExecutor 生成 `lasercnc.external-effect-signature` v1 形状。AppKernel 恢复所有权时还会认证 command/session/project/document、请求与解析版本、策略、副作用等级、资源、guard 和 arguments；直接调用独立 Persistence 组件不能替代该 Host 认证链。
- Executing 在重启后只映射为 Interrupted、ReconcileRequired 或 Indeterminate；不会自动执行 handler。Safe/Idempotent 是否允许显式重试由 ReplayPolicy 决定，ReconcileOnly/Never 保持人工协调边界。
- 读取未知策略返回 `Persistence.InvalidExternalEffectPolicy`，未知状态返回 `Persistence.InvalidExternalEffectState`；合法但不相容的 state/policy 返回 `Persistence.ExternalEffectStatePolicyMismatch`。不能把未知文本映射成 Never、Indeterminate 或默认状态继续运行。
- signature/outcome 的 `Value` 字节、深度与总量仍归 C6c；系统时钟和同步执行取消边界分别归 C6c/C6d。本节点不把状态正确性扩大成容量或 deadline 签核。

## Diagnostic 契约

`DiagnosticStatus` 的闭集为 Healthy、Degraded、Unhealthy、Unknown；Unknown 是合法的诊断状态，闭集之外的底层值不是 Unknown。`recordDiagnostic()` 在序列化和写入前拒绝未知值与纪元前 `observedAt`，统一返回 `Persistence.InvalidDiagnosticReport`，且 `diagnostic_history` 不增加记录。

Diagnostic 当前只写和只读 `lasercnc.diagnostic-report` v1，载荷绑定 `diagnosticId/status/summary/details/observedAtMs`，并与控制列、正序 sequence、非负时间和 SHA-256 摘要交叉认证。摘要正确但版本不是 1、状态文本未知或载荷与控制列不一致时均失败关闭；摘要本身不等于格式受支持。插入必须恰好一行，否则返回 `Persistence.DiagnosticInsertFailed`。

DiagnosticsService 的运行期 Unknown 归一、latest 顺序、并发和 exporter 资源隔离由 C6b6/C6b10–b12 管理；本文件只冻结直接持久入口和读取格式，不重复签核观察服务的内容预算。

## Recovery 与 Session DTO

`RecoveryReport` 是 `recover()` 在完整认证 Journal、Snapshot、对象、History、修订链和身份后构造的输出，字段 `documents/historyCommits/latestJournalSequence/journalRecordsReplayed` 不是可重新提交的恢复命令。它没有独立 wire 版本，实际兼容边界由 state-journal v1–v4、document-snapshot v1–v3、对象记录版本和外层 LCNCSN02 共同决定，不能把 `RecoveryReport` 的 C++ 字段布局当作跨工具链 ABI。

`PersistenceSessionStatus` 和 `PersistenceOwnershipState` 同样是 `sessionStatus()` 的只读观察结果：NotRequested/Unconfirmed/Acquired 描述本对象最近一次准入证据，`ready` 描述持久服务是否初始化；`lastAdmission` 是后端读回材料。Acquired 不是释放所有权、绕过隔离或执行恢复的授权令牌。

`ExecutionOwnership` 及 `executionOwnerships()` 是 AppKernel 友元私有恢复能力，不是公共 DTO。它从已认证 Task request 和 ExternalEffect signature 提取 Project/Document 根，用于一次性 legacy 目录迁移和启动归属校验；不能增加公开 SQL/恢复旁路。

## 兼容、回滚与后续边界

本节点没有数据库迁移和新持久格式。合法 v1/v2 command outcome 与现写 v3 保持读取；Diagnostic 仍严格为 v1；ExternalEffect 的控制列和签名 v1 不变。旧二进制仍只能在其原有读取能力内工作，回滚必须使用可执行文件、数据库、Snapshot 与 Asset 的成套备份，不能只替换二进制解释前向材料。

新增回归覆盖：幂等占位伪报 0/2 行的真实红灯和回滚后重试；ReplayPolicy 4/255、DiagnosticStatus 4/255 及纪元前时间的零写入；摘要有效但不支持的 command outcome/diagnostic 版本；command outcome v1/v2 精确兼容；ExternalEffect 未知策略、未知状态和状态策略不一致三类读取拒绝。

本节点不代签 Value/字符串/集合预算、同步 handler 的抢占取消、Task/Workflow/Script 终态有界保留、容量或跨工具链 C++ ABI。下一步先对账全部 71 个公共头和 C6b1–b20 的错误码/权限/版本清单，确认 C6b 无遗漏后，再依次进入 C6c、C6d、C7、C8 和 ST1D。
