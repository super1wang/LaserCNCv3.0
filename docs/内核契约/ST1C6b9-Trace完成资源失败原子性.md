# ST1C6b9 Trace 完成资源失败原子性

## 问题与契约

`ITraceSpan::end` 是 `noexcept` 且只接受第一次结束。旧实现先把句柄标记为已结束，再构造非法终态诊断和执行 completion；任一分配异常会被吞掉。若异常发生在 completion 删除活动项之前，句柄析构因已经结束而不再补偿，服务永久保留一个调用方无法操作的活动 Span，形成句柄状态与活动表分裂。未显式结束的句柄在构造 `Trace.SpanAbandoned` 时存在同类问题。

现在每个已激活句柄除正常 completion 外还直接持有共享 Core。显式结束或析构路径捕获资源异常后，执行不分配内存的活动项删除；若正常 completion 已经删除活动项，该删除保持幂等。因此，结束一经消费，在所测内存分配失败下不得留下活动身份，句柄析构也不得重新发布第二次完成。

本规则不承诺资源耗尽时完成记录或 exporter 通知必定落地：正常路径仍先删除活动项，再复制到有界完成窗口和 exporter 快照；后续分配失败允许丢失这次尽力观察。SpanId 是否可重试必须与实际完成窗口一致：已保留时仍冲突，未保留时可重试。该取舍避免用无界预留或隐藏堆分配伪造强持久保证。锁获取自身抛出等非分配系统失败不在本节点签核范围。

## 故障矩阵

独立 Release/ASan 进程对四条路径逐分配点执行：startSpan 14 点、合法完成 11 点、非法终态完成 31 点、析构 abandoned 28 点。每个完成点既注入一次性失败，也注入从该点起持续失败；验证活动表只剩无关 Span、句柄析构幂等、旧窗口不被篡改、SpanId 重试与是否保留记录一致，最终活动数为零。Debug 替换分配器仍只做链接/启动 smoke，不能代签故障矩阵。

本节点不覆盖活动总量预算、记录内容预算、Metrics/Diagnostics 资源耗尽、Diagnostics latest 并发顺序、操作系统锁失败、跨进程 trace 汇聚或上层模块。
