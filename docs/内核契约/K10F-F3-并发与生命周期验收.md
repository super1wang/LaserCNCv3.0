# K10F F3：并发与生命周期验收

## 状态

F3A/F3B 已实现规划要求的矩阵，最终版本汇总验证仍在运行；当前文档不是提前签发的认证。全部证据补齐后再更新本节、路线图和远端节点。F4/F5 未完成，Kernel 1.0 不处于 Frozen 状态。

## 规划逐项映射

| 原规划项目 | 当前证据 |
| --- | --- |
| 并发 Query | F3A：16 路 Query 同时处于 handler，返回相同只读材料，不增加 Revision/Journal/History |
| 并发相同 Idempotency Command | F3A：16 路同键请求，只有 1 次 handler/提交和 15 次 replay；新内核仍重放原回执 |
| Revision conflict | F3A：8 个基于同一 Revision 的候选，1 个持久胜者、7 个冲突；恢复后无失败候选材料 |
| Task cancellation race | F3B：真实 BS worker，完成前/后及 8 路 cancel 与完成竞争；检查终态、资源复用和重启 |
| Workflow cancellation race | F3B：真实两步 DocumentWrite，完成前/后及 8 路 cancel 与执行完成竞争；检查已接受提交、步骤 attempt 和恢复终态 |
| Document close vs Query | F3A：Query 活动时拒绝 close；Closing 期间 16 路 Query 全部拒绝，close/open 后恢复执行 |
| Document close vs Task | F3B：Running/CancelRequested Task 阻塞 close；真实完成后 close/open 成功 |
| shutdown vs active runtime | F3A：活动 Command/Query/Transaction 拒绝 shutdown；F3B：实际 Workflow 步骤拒绝 shutdown，Task 超时保持 Stopping/所有权，完成后可收尾 |
| Module startup failure rollback | F3B：20 轮 × 注册返回错误/注册异常/后继 start 失败；验证全部实际注册表清理、服务对象释放及健康新组合 |

每种 Command/Query/Task/Workflow 用例每次固定 20 轮，每轮新建内核/数据库。Module 用例每次执行 60 次失败组合与 60 次健康对照。竞态中的合法胜者不固定；明确序的前置/后置用例分别保证取消优先和完成优先语义，不能依赖随机竞争恰好覆盖两个次序。

## 实测修复

F3B 发现并修复 `Scheduler::requestCancel` 把已 `CancelRequested` 的运行任务再次取消为终态的问题。现在重复取消只维持请求状态，实际完成回调才回收运行容量和独占资源。失败与修复后的证据见 [F3B 记录](K10F-F3B-取消竞态与生命周期压力.md)，架构规则 117 固定此不变量。

测试辅助代码之外没有新生产能力或公开 API。F3A 首轮活动租约含义修正、F3B 模块健康对照补 executor 均属于测试构造修正，未通过放宽内核检查来使测试通过。

## 结论范围

F3 的“0 flaky / 0 deadlock / 0 partial state”只针对记录中的测试配置、轮次及交错，不是对所有可能线程调度的数学证明。同步点有 5 秒上限和异常释放保证；CTest 进程超时只是挂起兜底，不等于所有生产 API 都有强制中断能力。

不把本矩阵视为性能/内存基线，不把显式取消解释为撤销已提交状态，不宣称任意多个 Host 可同时配置或销毁同一个 AppKernel。没有引入 GUI、CLI/RPC、AI、CAD/CAM、Machine 或 Process 模块；物理机安全与存储断电保证也不在本验收范围内。
