# ST1C6b2 日志文件身份与轮转准入

## 范围与状态

承接 [C6b 逐项审计](ST1C6b-公共契约逐项审计.md)，基线 `e06add6`。本节点修复配置期日志输出和轮转目标的静态文件身份冲突；不增加日志服务公共方法、业务模块或新依赖。最终 Debug 426/426、定向 20 项各三次、ASan 68 项各三次、探针另 3/3 及纯生产/边界通过，见 [交付记录](../阶段交付/2026-09-04-ST1C6b2-日志身份与轮转文件准入.md)。本地检查点成立，完整 C6b、C6–C8/ST1D 均未签核。

## 输入与拒绝语义

SpdlogLogOptions 的五个字段及默认值不变。C6a/b1 的非空、NUL 和 UTF-16 完整性检查先执行；本节点再预检每个已启用文件输出的当前文件及 1..rotatingFileCount 的轮转目标，然后才构造任何 sink。

1. 轮转名称必须使用锁定 spdlog 的实际 calc_filename，不能自行假定固定后缀。正常扩展名和无扩展名的 base 与 rotation 冲突均须拒绝。
2. 对尚不存在的目标，普通 Win32 路径只使用 GetFullPathNameW 的绝对化和名称规范化，不能手工裁剪中间目录字符。提取父目录后以扩展路径固定已解析拼写，再向上寻找实际存在的目录，避免目录从“中间组件”变成“末组件”后被二次规范化。按其文件身份、相对剩余名称和目录大小写策略比较；父目录别名不得生成两个独立的逻辑输出。原生扩展路径保留原始名称语义。
3. 对已存在的目标，以 OPEN_EXISTING/FILE_READ_ATTRIBUTES 读取磁盘对象元数据，比较卷号和 128 位文件 ID，不能仅比较路径字符串、大小或内容。不同路径的硬链接，包括同一 sink 内两个历史文件的硬链接，都须拒绝。
4. 文件名空间或物理身份重复返回 Validation/Logging.InvalidOptions。无法读取必要元数据、对象类型错误或不支持所需查询时，返回 Infrastructure/Logging.InitializeFailed，不把未知身份当作互不相同。不会为预检创建文件、目录或修复名称。
5. 使用该目录的大小写策略，不全局折叠名称。大小写敏感目录中的 events.log 与 EVENTS.LOG 可独立输出；本机正例覆盖已存在/未创建文件、直接目录/新建子目录，并检查两个输出和两套轮转文件。
6. rotatingFileCount 超过锁定 spdlog 的 MaxFiles=200000 时，提前返回 Logging.InvalidOptions。以前此值会由库抛错再映射 InitializeFailed；这是错误分类调整，未新增公共字段或缩小库原本允许的数字范围。上限的容量可用性仍须 C7 验证，不能把数值准入当作该规模的生产性能承诺。

同一物理文件的备用数据流不作为相互独立日志文件；普通文件路径和盘符/目录的解释由 Windows 提供。本节点不宣称所有设备命名空间、特殊流、文件系统及动态别名组合已得到穷尽认证，未验证环境须按 C5/C6 后续逐项保留。

## 生命周期、信任与 I/O 边界

此准入面向配置期间稳定、可信的文件根。检查后外部进程替换符号链接、重命名目录、修改大小写标志、制造新硬链接，或并发改变进程当前目录，不受此静态预检保证。运行中的跨实例文件占用/轮转互斥、恶意替换防护及日志物理断电耐久不是本节点已实现能力；不得把短时读取元数据的句柄当作持有整个日志寿命的安全租约。

参数/身份预检不等于跨 sink 的任意 I/O 原子事务。实际 Windows 测试证明：以不共享模式打开的文件仍可能允许 FILE_READ_ATTRIBUTES 元数据查询；随后 spdlog 的数据写打开才失败。此时 InitializeFailed 正常传播，先创建的另一个空输出可能保留，原锁定文件内容保持。此行为与“已知冲突在创建前拒绝”分开验收，不通过改写已知冲突用例来宣称完全回滚。

只有运行时可写权限才能决定后续写入成功；身份读取成功不授予写权限。日志 write/flush 的错误和同步调用边界保持不变，不获得 Task 强制取消或 Host 执行权。

## 证据与成本

新增 [logging_path_identity_tests.cpp](../../tests/unit/infrastructure/logging_path_identity_tests.cpp) 包含 11 个 CTest、36 个内部场景：文本/物理别名、轮转命名空间、父目录别名、大小写敏感与普通新目录正例、超上限拒绝、错误目标类型、后续共享失败，以及真实尾随空格/多点中间目录的别名与区分。夹具保留所有文件；大小写敏感测试只在自己新建的空子目录设置 Owner Rights ACL 与大小写属性，不修改仓库、父目录或既有用户文件权限。

算法枚举每个 sink 的 base 与所有保留轮转目标，默认两文件输出各四个名字。临时集合和元数据查询随配置的保留数增长，集合插入约 O(N log N)，路径/元数据 I/O 另计；不得把此实现描述为常数开销。C6c 明确日志配置/记录预算，C7 测量极端保留数、深目录及已有文件场景，必要时在保持身份正确性的前提下优化。

新增私有实现与头仍只位于 Infrastructure：spdlog 命名/冲突集合留在 logging/spdlog，Windows 元数据读取放在 persistence/filesystem/windows，不放宽既有第三方/系统 API 目录门禁。公共头、日志内容格式、持久数据库/Journal/Snapshot/Asset 格式不变。私有头扫描缺口仍归 C8。日志目录支持范围需要真实环境验证，不能把本机 NTFS 证据扩展为 ReFS、网络盘、设备路径或任意 Windows 版本认证。
