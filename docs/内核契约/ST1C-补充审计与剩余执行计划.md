C1a 时 `IPersistenceBackend` 只有 SQL 与事务方法，SQLite Adapter 只显式设置外键、错误码和 busy timeout，`beginTransaction` 使用 `BEGIN IMMEDIATE`。C5a/b 已实现显式会话准入端口、实际文件独占、策略读回及初始化事务前强制接入，并完成夹具迁移与本地门禁。Benchmark 改为准入后采集实际配置，但环境记录本身不等于运行期准入门禁。

- 所有权在 schema 初始化及任何 abandoned claim 恢复之前取得，跨恢复与正常运行保留；第二个 Host 失败不能改写第一个 Host 的状态。故障代理必须转发所有权契约，不能有默认成功的伪实现。
- 验证同进程/跨进程第二实例、路径别名、正常释放和进程中断后的接管；明确连接、Host 停止、后台任务 drain 和所有权释放顺序。C2c 的未结束任务不得因 shutdown 超时提前让出所有权。
- 耐久策略必须设置并读回验证，失败拒绝启动，诊断记录实际生效值；不把默认值、配置意图或性能报告当作保证。文件系统及非本地路径的支持边界要明确，不承诺硬件断电结果。
- C1b 在同一写事务内校验项目与文档前置修订、合法后置变化和所有权；区分新提交与已验证的相同 TransactionId 重放。失败不能发布业务状态、History 或成功提交事件；失败诊断/幂等失败状态仍按既有契约处理。不能只检查全局序号或 SQL INSERT 成功。

上述是完整实施要求。C5a 组件证据不能替代 C5b 强制初始化集成，未达到全部要求前不得标记 C5 已完成；详见 [C5 设计与证据](ST1C5-持久化Host独占与耐久准入.md)。

## Project / Document 与公共入口边界

- Project 管身份、生命周期、目录和整体一致性，允许 0:N 文档；Document 管事务、业务状态、局部修订和历史。
- Module、输入 STEP、共享 View 不与 Document 一一对应；内核多项目/文档能力不强迫产品第一版同时激活它们。
- 项目业务配置未来可用普通 Manifest Document，不在 ProjectRuntime 再造业务仓库或 Undo。
- ManufacturingDocument、机台包、工程包、共享视图和 ManufacturingRelease 只记录后续组合原则，本阶段不实现；实时控制器状态不是 Document 真值。
- 入口清单区分执行活动、生命周期控制、诊断观察和内部恢复，避免关闭/打开被普通租约自阻塞。

## 签核规则

新增项映射 ST1/ST2/ST3、TX1/TX3、ET4、PE2、SA3 和 RE。历史 F5C/ST1A/B 成绩保留原提交范围，不覆盖新交错、身份域、非零修订和资源边界。清单按最终注册用例和标签生成，不硬编码旧 264/284 或故障数。

证据包含提交、工具链/依赖、配置、唯一用例数及重复次数、退出状态、日志摘要、支持边界和未执行项。自动化全绿不替代 GUI、设备安全或物理断电验收。
