# ST1C5c 存储支持矩阵与离线恢复

## 状态与适用范围

承接 [C5 独占与耐久准入](ST1C5-持久化Host独占与耐久准入.md)、C2c 最终排空及 C3/C4 恢复认证。起点为 C4 大节点 `432434f`。本节点把“实现允许”“本机真实验证”“未验证”“不支持”分开，补成套离线归档恢复测试，不新增产品备份命令、在线备份服务、工程包或上层模块。

本机检查点通过：新增六场景 Debug 三轮，相关 Debug 35/35、定向 ASan 35 项各 3 次（105/105）、纯生产/架构通过。支持矩阵已建立，未验证环境仍明确保留；尚未签核完整 C5/ST1D，更不能宣布 Frozen。源码和结果以 [C5c 交付](../阶段交付/2026-09-04-ST1C5c-存储支持与离线恢复验证.md) 为准，下一步 C6。

## 支持与证据矩阵

| 环境或能力 | 实现事实 | 当前真实证据与边界 |
| --- | --- | --- |
| Windows x64 / 本机固定 NTFS 数据库 | SQLite 实际文件句柄 + 卷信息核验 + 独占区间锁；初始化前强制准入，DELETE/EXTRA/foreign_keys 读回 | C5a/b 与 C2c 已验证同/跨进程拒绝、接管、策略漂移及最终析构；本轮复验。当前机器是 Windows 11 专业版 Insider Preview 10.0.27749，C/J 为 Fixed NTFS，不代表所有 Windows 版本或磁盘硬件认证 |
| ReFS 数据库 | 准入白名单允许 ReFS，保留现有实现 | 本机没有已识别的 ReFS 测试卷；实机锁、崩溃恢复、文件发布及成套恢复均未验证，不能列为已认证配置。不为获取绿灯删除实现分支 |
| 非固定卷、网络共享、非 NTFS/ReFS 数据库 | acquireFileOwnership 依据 SQLite 句柄解析的卷属性拒绝；错误为 HostSessionStorageUnsupported | 当前缺少对应实机介质/共享，只有源码证据，真实拒绝分支待验证；不得把 NTFS 成功测试当作这些环境的拒绝证明 |
| 不提供原生文件句柄的 SQLite VFS | HostSessionUnsupported；公开 options 不提供 VFS 选择器 | 非默认 VFS 环境未实测。不添加生产 testMode/VFS 绕过选项；当前本机测试使用锁定 SQLite 默认 Windows VFS |
| 私有 :memory: | 独立连接，persistent=false，ownership=private-memory，journal_mode=memory | C5a 组件及本轮回归验证；仅内存会话，不是文件耐久支持，文件资产存在不等于数据库状态可重启恢复 |
| 数据库相同/点路径/大小写/硬链接别名 | 实际文件锁仲裁，而非路径字符串旁路锁 | 已验证活动 Host 排他、正常释放后的接管；硬链接用例只证明排他，**不认证更换硬链接路径后的崩溃恢复**。数据库与 SQLite 侧文件必须按一致路径管理，不能因锁测试通过就轮换别名恢复 |
| 快照/资产目录 | 文件适配器独占临时文件、flush、不覆盖发布、身份/摘要校验；资产复用快照文件层 | 本机 NTFS 的发布、损坏拒绝、进程中断与恢复有测试。SQLite 的卷检查只认证数据库所在卷，并不自动认证这两个目录；文件根须另行确认位于受信任的已验证本地存储 |
| 干净、成套离线归档恢复 | Host/实际后台访问者全部销毁后，在无外部写者时复制数据库、快照、资产到全新目录 | 本轮测试两代完整归档、旧数据库配合法不可变文件超集；新 Host 实际 Undo/Redo、再次重启与源归档摘要不变。不是在线复制或崩溃现场修复证明 |
| 不完整归档 | 恢复验证引用材料；错误保留 cause | 本轮缺快照、缺当前资产、缺历史资产均拒绝，连续两个新 Host 仍拒绝，恢复副本及原归档文件摘要不变。不能据此声称所有任意跨代组合都能被检测：未被引用的额外不可变文件允许存在 |
| Interrupted Opening / Failed Host | C4 明确保留诊断、不自动重开、不自动改 SQL 状态；Failed Host 普通 shutdown 拒绝，析构负责最终释放 | C4c 已有运行期/启动失败及连续新 Host 验证。本节点不新增通用 repair API；无完整可信归档时保留故障材料，不能承诺自动救回 |
| 多写者/原始 SQL 写者/活动文件替换 | 不属于可信单 Host 协议；底层 SQL 工具可绕过内核端口 | 不支持并行多写者，不提供恶意同进程或外部写者隔离；同一快照/资产根可能被其他实例使用，数据库锁不等于这些目录的全局备份锁 |
| 物理掉电、网络盘、云同步根、跨机器/跨工具链 | 本阶段没有相应完整认证 | 进程终止、EXTRA/flush、ASan 或 CTest 均不能代签硬件掉电/网络存储保证。跨工具链 C++ ABI 不承诺，格式兼容另归 C6 |

数据库后端的卷拒绝发生在 acquireHostSession，而不是 `open`：后者为连接/低层适配器入口，可能已创建空数据库文件。强制保证是 **内核初始化 schema 和恢复 SQL 之前** 取得会话，不能扩写为“不支持路径上完全没有任何文件系统触碰”。快照/资产 root 的 create 同样可能创建目录；这不是已经取得整个存储集合的写入独占权。

## 成套离线恢复流程

1. 停止新执行并按 Kernel 协议结束已有任务、事务和外部活动。shutdown 返回或超时本身不是所有权释放证明；销毁 Host，等待最终 drain 以及实际执行器/适配器释放。共享快照/资产根的其他访问者也必须退出，确认不存在原始 SQL、同步软件或其他写者。
2. 保留原始数据库、快照、资产及现场侧文件。干净正常停机的本轮测试明确没有 `state.db-journal` / `state.db-wal`，然后才复制；若存在崩溃现场、失败写入或未确认的侧文件，不套用“只复制主库”的测试结论，也不得删除、混配或换名这些材料。
3. 将同一停机状态的数据库及其实际需要的侧文件、全部快照文件和资产文件复制到全新归档目录。不要覆盖旧归档或把不同时间点的目录随意拼接。记录相对路径、长度、摘要、内核/依赖版本、配置和源根；摘要用于完整性核对，不是恶意篡改认证或加密签名。
4. 恢复时再从归档复制到另一个全新候选目录，配置兼容的内核版本及各文件根后创建新 Host。成功 bootstrap 后核对身份、状态、修订、History 和资产，并执行适合数据集的只读验证；本轮夹具额外实际 Undo/Redo，再次重启核对。原归档始终不作为可写运行目录。
5. 启动拒绝时保留结构化错误及 cause，销毁 Failed Host，保留候选和原归档。不得直接编辑 Catalog/Journal、跳过资产/History 认证或反复把 Opening 改成 Detached 来启用。只能选择另一份完整可信归档/兼容配置，或进入独立且明确授权的恢复调查；没有归档不等于可以宣称已恢复。

SQLite 官方明确指出：活动事务期间的普通文件复制可能产生不一致副本，失败事务相关的 journal/WAL 必须与主库配套保留；不同硬链接路径还可能使用不同侧文件。[SQLite 损坏与备份边界](https://www.sqlite.org/howtocorrupt.html)。SQLite 在线 Backup API 的对象是数据库；结合本仓库独立文件适配器的实现，它不会同时替内核认证快照与资产集合。[SQLite Backup API](https://www.sqlite.org/backup.html)。因此本节点只验证静止、完整、可信数据集的离线复制，不把在线数据库备份等同于应用级成套备份。

新 LCNCSN02 文件格式只有前向读取兼容；回退旧二进制必须配合该版本能读取的完整归档，不能只换二进制。本次测试用同一受测版本恢复两代数据，并未运行旧二进制或证明反向格式兼容。

## 六场景的实际判定

| 场景 | 结果要求 |
| --- | --- |
| 第一代完整数据库/快照/资产 | 恢复修订 1、对象及 History，Undo 删除首对象、Redo 还原，再次新 Host 保留结果 |
| 第二代完整集合 | 恢复修订 2 与替换后的资产，Undo 实际读取第一代历史资产，Redo 回到第二代，再次新 Host 保留结果 |
| 第一代数据库 + 第二代快照/资产目录 | 若第一代所需不可变文件仍完整存在，允许恢复第一代；额外文件不自动作为新业务状态导入，也不据此允许清理孤儿 |
| 第二代数据库 + 第一代快照目录 | KernelRecoveryFailed → Snapshot.NotFound，未安装可执行文档 |
| 第二代数据库 + 第一代资产目录 | RecoveryAdmissionFailed → Asset.StateAdmissionFailed，cause 指向第二代当前资产 |
| 第二代集合遗漏第一代历史资产 | HistoryAdmissionFailed → Asset.StateAdmissionFailed，cause 指向第一代历史资产；当前对象文件完整仍不得绕过 History 恢复验证 |

三种负例均连续创建两个新 Host 验证拒绝和文件摘要不变；未自动调用业务 Handler。测试保留源、两代归档和候选目录，只有历史资产负例明确删除了候选副本中的一个文件，原资产与两代归档均保留。此测试不是生产导出/导入接口，也不是强制中断进程的测试，独立进程证据由既有矩阵承接。

## 后续验收

本轮先完成上述本机检查点及证据，C5 的最终支持范围与受影响项随 ST1D 重新签核。ReFS、非本地/非固定卷真实拒绝、非默认 VFS 等保持未验证；新增硬件或系统环境不能从本机结果推导通过。C6 登记文件集合、启动错误 cause、版本/回滚边界与输入预算；C7 测量真实状态和文件量；C8 将环境清单、重复次数、脚本子步骤和证据完整性纳入可重复门禁。
