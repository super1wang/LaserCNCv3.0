# ST1C6b14 资源声明枚举与算术准入

## 契约

`ResourceClaim` 是 Task 与外部 Effect 进入内核资源仲裁的公开结构化声明，`ResourceManager::configure` 是组合期容量配置入口。C++ 枚举可由任意整数强制构造，`size_t` 相加也会回绕，因此资源模型不能依赖默认分支、比较副作用或无符号算术自然形成安全结果。

本节点固定以下准入规则：

| 入口/字段 | 合法值或运算 | 拒绝错误 |
| --- | --- | --- |
| `ResourceManager::configure.kind` | CPU、DiskIO、GPU、OCCT、ProjectRead、ProjectWrite、MachineController、CollisionBackend | `Task.InvalidResourceKind` |
| `ResourceClaim.kind` | 同上八种具名值 | `Task.InvalidResourceKind` |
| `ResourceClaim.access` | Shared、Exclusive | `Task.InvalidResourceAccess` |
| 同一规范化资源的 Shared units 聚合 | 每项大于零，累计值可由 `size_t` 表示 | `Task.InvalidResourceUnits` 或 `Task.ResourceUnitsOverflow` |
| 外部 Effect 的资源 kind/access | 同上合法枚举 | `Command.InvalidEffectResourceKind` / `Command.InvalidEffectResourceAccess` |

配置入口在取得资源锁及修改槽位前验证 kind，拒绝不改变现有资源快照。运行时仲裁先验证全部声明并在每次累加前检查上界，之后才取得资源锁、建立默认槽位或修改占用状态；失败不产生部分资源持有。外部 Effect 注册在 Registry 写入前验证资源枚举，拒绝不留下可发现的半注册命令。

`ProjectWrite` 继续与 `ProjectRead` 规范化到同一槽并强制 Exclusive；调用者即使为 ProjectWrite 填写合法 Shared，也不会放宽写互斥。未配置槽的容量仍默认为 1，零 units 与同槽 Exclusive/混合声明继续使用既有错误。本节点不改变这些已声明语义。

## 任务终态与外部 Effect 边界

普通 Task 的声明由 Scheduler 接管后在调度泵中仲裁，因此提交成功只表示任务身份已被内核接受。若资源声明非法，任务按既有完成链进入 `Failed`，保留对应 Validation Error，handler 不执行；这不是同步 `submit` 的参数拒绝，也不表示非法任务曾取得资源。

外部 Effect descriptor 属于组合期注册材料，未知 kind/access 在命令注册时直接失败。即使未来存在其他内部构造路径，执行前仍经同一个 `ResourceManager::tryAcquire` 防线；失败发生在 durable effect claim 和用户 handler 之前。资源验证不授予文件、发布、机台、运动或激光权限，SideEffect、Guard、Idempotency 和 ReplayPolicy 仍由各自契约独立准入。

## 兼容与精确边界

这是非法输入行为收紧：此前未知 kind 可能创建不可解释槽位，未知 access 会落入 Shared 分支，重复 Shared units 还可能回绕为较小值并实际执行；这些情况现在稳定失败。公共头、八个 ResourceKind 数字、两个 ResourceAccess 数字、ResourceClaim 字段、持久格式、SQLite 版本和依赖均未修改，不提供把未知旧值映射成合法资源的迁移。

本节点只处理枚举闭集和单任务重复 Shared 声明的算术上界，不制定 capacity 的产品支持最大值，不限制声明数量、ResourceId 字节数、全局槽位数、等待队列或终态保留。统一输入/输出预算归 C6c，Task 取消/超时与有界保留归 C6d，容量实测归 C7。

本节点不新增工程包、CAD/CAM/Process/Machine 实现、GUI、产品 CLI/RPC/AI 或设备驱动。
