# K10D 模块治理与执行网关契约

## 1. 阶段状态

K10D 已验收。D1 闭合模块贡献声明、所有权与回滚；D2 闭合 Host 执行、发现与注册的类型边界。本阶段只修改 Application Kernel、基础设施测试与中文文档，没有实现或扩展 CAD、CAM、Machine、Process、Collision、Qt、产品 CLI/RPC 或 AI。

## 2. 模块贡献治理

模块只能在 `IModule::registerComponents(ModuleRegistrar&)` 中发布贡献。`ModuleDescriptor` 必须按类别声明 Service、CommandKey、QueryKey、Task、Workflow、Script、Event 与 Capability；Command/Query 所有权按名称和版本的精确键核验，其余类别按稳定名称核验。

ModuleRuntime 在回调前拒绝模块内重复声明与跨模块所有权冲突，在回调后比较声明集合和实际成功注册集合。未声明注册、漏注册、被回调忽略的首次错误均阻止 initialize。注册或后续生命周期失败时，已经发布的实际 Registry 贡献按逆序移除。

Event 与 Capability 当前仅形成显式贡献审计事实，不代表存在独立事件 Schema Registry 或授权策略 Registry。

## 3. 唯一 Host 执行面

`AppKernel::execution()` 返回 `ExecutionGateway`。网关统一提供：

- Command 与 Query 执行；
- Workflow 启动、推进、取消与快照；
- Script 执行、推进、取消与快照；
- 由受治理异步命令产生的 Task 的观察、等待与取消；
- Module、Command、Query、Task、Workflow、Script 描述符目录。

网关不提供 Task 直接提交、Registry 注册、TransactionManager 或可变 DocumentStore。异步 Task 必须由 Command、Workflow 或 Script 的受治理链产生，不能绕过 Capability、Scope、Schema、幂等与观测规则。

## 4. AppKernel 公开边界

`AppKernel` 已移除 CommandRuntime、QueryRuntime、TaskRuntime、WorkflowRuntime、ScriptRuntime getter。ServiceRegistry、ModuleRuntime 与 Command/Query/Task/Workflow/Script Registry 只保留 const 发现视图；安装模块仍只允许配置期调用 `addModule()`。

因此 Host 无法从 AppKernel 获得 handler 注册、`TaskRuntime::submit` 或原始执行入口。测试也使用位于 `tests/support` 的 IModule 构建器进入同一 ModuleRegistrar 链；该辅助代码不属于生产目标。

## 5. 防回退门禁

`architecture.kernel_public_api_boundary` 除第三方类型与实现目录隔离外，还扫描 `app_kernel.hpp`：一旦重新出现可变 Service/Module/Registry getter 或五类原始执行 Runtime getter，配置测试直接失败。编译期类型断言固定五类 Registry、ServiceRegistry 与 ModuleRuntime 的 const 返回类型。
