# ST1C6b21 71 公共头与兼容清单最终对账

## 结论与边界

本节点以 `9ea3429` 为实现基线，对 [C6 起始公共头清单](Kernel-1.0-公共头清单.md) 和 [C6b1–b20 逐项审计账本](ST1C6b-公共契约逐项审计.md) 做最终交叉核对。当前 `include/lasercnc` 仍为 71 个 `.hpp`，目录分布为 Foundation 7、Infrastructure 8、Kernel 7、Messaging 2、Observability 5、Persistence 1、Platform 6、Runtime 29、State 6；71 个当前文件的 SHA-256 与 C6a 基线全部一致，差异数为 0。

因此，C6b1–b20 的行为收紧没有造成未登记的公共头漂移；71 个头均已在下表落实到公开面、权限分类和后续预算/寿命节点。这里签核的是 C6b 的“公共声明、错误、权限、持久格式与兼容边界可追溯”，不是跨工具链 C++ ABI 承诺，也不是 Kernel Frozen。C6c、C6d、C7、C8 和 ST1D 仍必须完成。

## 71 个公共头逐头对账

## 权限与所有权最终分层

| 阶段 | 可达能力 | 明确禁止的推导 |
| --- | --- | --- |
| 组合期 | ModuleRegistrar、Registry、基础设施/持久组件构造与配置 | 独立构造 PersistenceService、Backend 或 Store 不等于运行中 Host 业务写权限 |
| Ready 后 Host | 通过 ExecutionGateway 执行 Command/Query/Task/Workflow/Script；读取目录、状态和观察快照 | 不可直接调用 TransactionManager、Scheduler 写入口、恢复安装或原始 SQL 修复业务状态 |
| 事务/执行内部 | Kernel 友元链提交文档状态、History、Journal、幂等及 Effect 状态 | 消息、日志、Trace、Metrics、Diagnostic 观察不能反向制造业务提交 |
| 恢复内部 | AppKernel 私有恢复链认证 Journal/Snapshot/Catalog/Task/Effect/Workflow 历史后安装 | `RecoveryReport`、`PersistenceSessionStatus`、CatalogVersion 或状态枚举不是恢复命令/授权令牌 |
| Platform adapter | 提供 SQL、文件、hash、配置和 executor 的最小端口 | 端口级成功不自动证明业务身份、耐久提交、物理落盘或设备安全 |
