# ST1C2b3：目录版本与失效

## 状态与范围

承接 `4f7959d`，本地检查点已通过，整体最终签核仍须 ST1D。只覆盖内核 Project/Document 生命周期目录；不实现 UI 缓存、订阅、产品接口或新的业务事务系统。

## 目录及令牌契约

两个 Runtime 新增 `catalog(optional<ProjectId>) -> Result<...CatalogSnapshot>`，默认返回该 Runtime 的全部条目，指定项目时只返回该项目作用域。不存在的作用域返回空集合，不创建项目、文档或计数条目。结果包含稳定 ID、生命周期状态、诊断错误，以及同一次持锁读取的 `CatalogVersion`。返回值拥有数据，不借出容器引用。

`CatalogVersion = { epoch[4 × uint32], projectId?, revision:uint64 }`，只比较完整令牌是否相等。同一 Runtime、同一作用域内计数单调；不同 epoch 或作用域的 revision 数值不能排序或单独比较。Project 与 Document Runtime 各有自己的 epoch，不能混用令牌。

- Project 目录仅表达项目身份、状态与错误；Document 目录表达子文档身份、真实归属、状态与错误。两次不同 Runtime 的查询不构成跨目录原子快照，也不把父项目是否可执行隐含在文档令牌中。
- 此目录是运行期生命周期目录，非 Persistence 的原始持久目录：Removed 文档不在条目中，墓碑仍由持久层保留并认证；也不是 Gateway 的模块/命令注册目录。
- 不包含 activities、Kernel accepting、业务内容或修订。旧 `list()/lifecycle()` 保留活动观察；令牌相等仅保证本目录内容未失效，不保证当前可执行或无人持有租约。
- 不新增 expectedCatalogVersion 写前置条件。本令牌不是权限、租约或 Compare-and-Swap；调用方不能拿它代替唯一生命周期入口的目标状态、归属、活动和整体准入检查。原业务 expectedRevision 仍不能用于生命周期控制命令。

## 失效规则

所有计数更新与相应运行目录变化在同一个 Runtime 互斥锁内完成，快照亦在该锁内同时复制版本与条目。

| 变化 | 版本行为 |
| --- | --- |
| 新建、配置期装载、attach/open、close/detach、remove | 全目录与受影响项目作用域递增；另一项目作用域不变 |
| Opening/Closing/Failed、错误变化、关闭预检后回退 Open | 可被观察的中间态均失效，最终状态恢复原值也不能复用旧令牌 |
| 未进入状态转换的重复创建、状态拒绝、短期活动阻塞 | 不失效 |
| 先预留 Opening 再因认证失败撤销 | 新增与撤销均失效，不把失败等同于“从未可见” |
| 只读查询、获取/释放普通活动租约、业务内容提交 | 不改变生命周期目录版本 |
| 成功恢复安装 | 涉及的作用域失效；新 Host 还使用新 epoch |

计数分配在可见状态变更之前完成；分配失败不允许状态先变化而版本仍旧。分配/恢复准备失败可能保守失效，不承诺计数恰好等于成功操作次数。删除最后一个条目仍保留已触及项目作用域的计数，避免删除重建后的 ABA；对应保留成本由 C6/C7 限定，不能无声回收成旧计数。

## 重启、溢出与兼容边界

- epoch 在 Runtime 构造时使用当前 C++ 标准库的 `random_device` 生成 128 位随机命名空间，不使用墙钟、地址或进程内静态序号。它是概率唯一缓存标识，不是密钥或持久业务身份；全零保留，不成功获取可用 epoch 则构造失败，不静默回退到时间戳。当前 Windows/MSVC 为验证平台，不宣称任意工具链随机设备语义相同。
- 持久/非持久 Host 都重新生成 epoch，旧 Host 的令牌不可因计数相同而继续使用。令牌不写 SQLite/Journal/Snapshot，无持久格式迁移；恢复后重新取得目录快照。无新增序列化或跨产品协议承诺，C6 须登记 DTO 与构造异常契约。
- uint64 计数耗尽后不回绕；受影响作用域的 catalog 返回 `Catalog.RevisionExhausted`，停止发布可复用版本。生命周期操作与旧只读诊断不因此伪装成功/可缓存，其他未耗尽作用域保持独立。恢复目录观察需协调新 Host，不允许 Host 重置内部计数。
- 构造函数为分配/epoch 获取可抛异常，原 ProjectRuntime/DocumentRuntime 的 noexcept 构造声明相应取消，析构置于实现文件。公共 DTO 不含第三方类型；不承诺跨工具链 C++ ABI。

## 验收要求

先失败证据为新增两个契约探针在旧实现编译成功后 0/2（0.24 秒）：缺少版本化快照接口，故不能完成 ABA 检查，不将此成绩描述为已复现数据竞争。后续要求验证：同状态 ABA、删除重建、真实 Query 在途活动、不相关项目、持久中间态/异常/部分关闭、三次同进程新 Host 恢复、并发一致快照和饱和计数。

12 项专项以及独立三进程探针已通过（13/13，12.20 秒），覆盖长任务关闭回退、非零真实业务提交、读取/写入错误和异常分支。测试专用进程探针依次 seed/read/read 同一库，断言 Closed/Detached、无加载文档和活动任务；六个 Runtime epoch 均不同，退出及格式均验证，原库和逐进程日志保留。它验证正常退出重启，不冒充物理断电或所有恢复路径认证。

最终完整 Debug 360/360（730.53 秒）、13 项各 10 次共 130/130（119.86 秒）、纯生产 Release 和架构/文档门禁通过。重复矩阵含 10 次三进程探针共 30 次独立进程执行。最终三配置与全部 ST1D 认证不由本节点替代；下一步 C2c。扫描和复制成本由 C7 实测，本轮不宣称 O(1) 全目录快照。完整证据见 [阶段交付](../阶段交付/2026-09-04-ST1C2b3-目录版本与失效.md)。
