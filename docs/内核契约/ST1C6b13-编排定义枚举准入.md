# ST1C6b13 编排定义枚举准入

## 契约

WorkflowDefinition 与 ScriptDefinition 是组合期进入内核的公开结构化定义。C++ 枚举可以由整数强制构造，因此 Registry 不能依赖 `switch` 只列出已知分支后自然通过；所有影响图形状、谓词解释或等待对象的枚举都必须在注册、引用解析和 Freeze 之前显式准入。

本节点固定以下值域与拒绝错误：

| 字段 | 合法值 | 未知值错误 |
| --- | --- | --- |
| WorkflowStep.kind | Command、Query、WaitTask、Assign、Assert、Barrier | `Workflow.InvalidStepKind` |
| WorkflowPredicate.kind | Exists、IsTrue、Equals、NotEquals、ArrayNotEmpty | `Workflow.InvalidPredicateKind` |
| ScriptNode.kind | Command、Query、Workflow、Wait、Assign、Assert、If、ForEach、Include | `Script.InvalidNodeKind` |
| Script 中复用的 WorkflowPredicate.kind | 同上五种谓词 | `Script.InvalidPredicateKind` |
| ScriptWait.target | Task、Workflow | `Script.InvalidWaitTarget` |

错误类别均为 Validation；Workflow 错误详情保留 workflow 与 step，Script 错误详情保留 script 与 node。拒绝发生在定义写入注册表之前，不留下可被 descriptor/resolve 发现的半注册项，也不延迟到首次实例执行或恢复时猜测未知枚举。合法定义的图形状、引用解析、摘要和执行语义保持不变。

## 兼容与证据

真实 Release 负例证明旧实现会接纳未知 Workflow step、Workflow predicate、Script node 与 Script wait target，四项均红灯。修复后矩阵扩为五个分支并补 Script predicate，共 10 条断言；全部非法值使用 `255`，实现按具名枚举白名单拒绝所有未声明值，而不是只针对该测试数字。

这是非法输入行为收紧：此前可能在组合期成功注册的未定义枚举现在立即失败。公共枚举的底层类型、已声明数字、DTO 字段、Workflow 检查点/定义摘要格式和 SQLite 版本均未修改；不存在把非法旧定义自动映射成某个合法分支的兼容迁移。定义本体仍由模块在每次组合期注册，实例恢复继续要求名称、Version 与合法定义摘要完全一致。

## 精确边界

本节点不签核 Workflow/Script 的字符串、Value、节点总量、嵌套深度、重试错误码、状态快照或检查点输入预算；这些仍归 C6b 后续账本、C6c/C7。未知持久状态、恢复 wire、同步推进取消/deadline 与终态保留也不由本节点代签。

本节点不修改公共头或引入新依赖，不增加文本脚本语言、GUI、CAD/CAM、设备、产品 CLI/RPC/AI 或其他上层模块。
