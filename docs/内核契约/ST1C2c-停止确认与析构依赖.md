# ST1C2c：停止确认与析构依赖

## 范围和顺序

承接 C2b3 `5259978`，只处理内核生命周期、调度器和执行器依赖，不扩展上层模块。C2c 不是单个 bool 状态修复，分两步保留独立验收：

| 子节点 | 实施与验收 | 状态 |
| --- | --- | --- |
| C2c1 | 停止请求与执行器确认分离；Configuring/Ready 使用同一确认路径；失败/异常可重试，模块不能提前撤销；禁止重启和重复/重入绕过；终态发布未结束不能报告成功 | 本地检查点通过：Debug 368/368、专项 8/8、停止相关 10 项各 10 次与纯生产/架构通过，见 [C2c1 交付](../阶段交付/2026-09-04-ST1C2c1-停止确认与失败重试.md) |
| C2c2 | Host 配置/启动/停止/销毁线程契约；工作线程调用停止的拒绝时机；非协作任务、失败状态和未启动执行器的析构保证；所有回调依赖及持久化所有权保留至真实 drain | 本地检查点通过：Debug 373/373、专项 15/15、15 项各 10 次、纯生产/架构和真实进程矩阵定向 ASan 3 轮通过；见 [C2c2 交付](../阶段交付/2026-09-04-ST1C2c2-最终排空与析构依赖.md)，不由 C2c1 代替 |

## C2c1 停止确认

Scheduler 新增内部停止请求、执行器确认及调用串行保护，不改变公共签名和持久格式。请求停止立即永久关闭 Scheduler 接纳；超时或执行器错误/异常均未确认停止，后续 shutdown 必须重新等待/调用执行器，不得因为 started 已清除而返回成功。执行器已配置但从未 start 也必须确认。未配置 Scheduler 可停止，但不能停止后再装配执行器。

成功条件为：没有运行任务、没有提交调度正在进行、所有终态观察与持久化尝试已经完成发布，且执行器 shutdown 成功。持久化尝试结束不等于写入成功，原有 persistenceFailures 和失败诊断继续保留。executor.shutdown 成功须代表不再接受工作、已保留的工作与回调全部完成；失败或异常不代表 drain，必须允许重试。当前等待谓词扫描保留的任务记录；C7 应联同 C6 终态保留上限测量停止成本，不宣称常数时间停止。

并发/回调重入 Scheduler::shutdown 返回 Task.ShutdownInProgress，不等待自身。start 在请求停止后拒绝；成功后的顺序重复 shutdown 不再重复调用执行器。AppKernel 原有 Kernel.LifecycleInProgress 保留，Configuring 和 Ready/Stopping 统一经 Scheduler。执行器错误或异常保持 Host=Stopping，不运行 Module::stop。

负 taskTimeout 在改变 Host 状态和准入之前拒绝，包含没有执行器的 Host。Scheduler 对极大正超时使用饱和截止点，避免时长换算/相加溢出。该修复仅覆盖 shutdown；其他 wait/deadline 输入的统一边界由 C6 核对。

超时不是硬实时保证：它约束 Scheduler 对任务/终态发布的条件等待，不能强制中断非协作 Handler、同步持久化/观察回调或第三方 executor.shutdown。尤其不能在超时后释放被任务引用的依赖、宣称工作已完成或重新开放 Host。C2c2 必须补齐销毁行为，不能仅加说明来关闭实际析构缺陷。

## C2c2 必须保留的验收

- 检查 Configuring、Ready、Stopping、Failed 的销毁路径，明确失败启动后的执行器是否仍可能保留工作。不能忽略 shutdown 返回值后按成员逆序释放运行时。
- 完成工作线程/回调上的停止与销毁契约，禁止自等待/自 join；Host 外部调用方负责对象寿命协调的范围应可验证，而不是用 atomic state 推导所有操作线程安全。
- 使用受控非协作任务验证：短超时返回时任务未完成；Task/Command/Query/Workflow/Script、资源管理、观察器、持久化与所有权仍有效；解除门闩后排空并按序释放。
- 验证执行器 shutdown 持续失败/抛异常的最终销毁保证；失败不得变成成功，也不能仅依靠 BsThreadPoolExecutor 的默认成员析构顺序。不得为通过测试提前抛弃依赖。
- 在真实 SQLite 所有权上验证未排空期间第二 Host 拒绝，排空与最终释放后接管；保留同进程与真实进程证据，不能用模块计数假执行器替代。
- 独立 Scheduler/TaskRuntime 的装配、准备任务/激活、停止与销毁由谁串行协调需要明确，Host 统一准入不能外推成独立组件的无限制并发保证。

## C2c2 实施契约

### 两种停止结果

普通 shutdown 是可检查、可重试的停止请求，失败/超时仍须保留 Host。析构不能返回失败给调用者，采用独立最终寿命屏障：关闭 Host/各 Runtime 接纳、请求任务取消、执行 ITaskExecutor::drainForDestruction、销毁执行器、确认 Scheduler 无在途任务/回调，然后停止模块并进入成员销毁。整个屏障覆盖 Configuring、Ready、Stopping、Stopped 以及失败启动/失败模块停止的 Failed 状态。

drainForDestruction 是强制纯虚端口，不提供默认成功。实现必须幂等关闭接纳并完成保留的工作和完成回调，允许无期限阻塞；无法证明安全时必须终止进程，不允许返回后继续释放依赖。析构也须满足相同保证。BsThreadPoolExecutor 在其成员退出前执行该屏障，工作线程自销毁或最终停止失败不会进入不安全的成员析构。普通错误 Result 和异常重试仍保留；不能把最终屏障的无返回值误读为普通 shutdown 已成功。

该端口与 isCurrentWorkerThread 查询是新增抽象接口，实现者必须适配，属于 C6 兼容性登记项，不承诺旧执行器实现源码无修改兼容或跨工具链 C++ ABI。同步替身没有后台保留项，但仍显式封闭准入；排队替身必须运行并清空已接受的工作/回调，不能只清空队列。

### 线程和对象寿命

- Host 所有者串行协调配置/启动，不与外部执行或销毁并发；不绑定某个固定 OS 线程，允许在无在途操作时移交协调责任。Ready 后公共执行与普通 shutdown 的交错继续由整体准入协调。
- 析构期间没有外部并发调用或外借句柄使用；内部仍在运行的任务及其完成回调是屏障要保护的对象。不能从自身任务/完成回调销毁 Host，也不能与在途生命周期或已接纳公开调用并发销毁。已能检测的违反立即调用 std::terminate，不继续成员销毁；生产退出时延取决于宿主/系统终止处理器。检测不是任意悬空句柄的通用内存安全保证。
- Scheduler 对其任务、调度与终态回调维护线程局部嵌套范围，并核验执行器所属工作线程。同步 wait/shutdown 在这些线程/回调内返回 Task.WaitFromExecutionDenied / Task.ShutdownFromExecutionDenied，防止自等待和单工作线程饥饿。该拒绝发生在关闭 Host 接纳前；同步执行器与观测回调也受覆盖。
- 独立 TaskRuntime/Scheduler 的所有者必须串行协调装配、start/stop 与完整 submit（包括持久接受和激活），停止接纳后排空执行器，再释放这些组件及借用依赖。Scheduler 不拥有外部执行器，不替调用者 join；析构检测到在途任务、终态未发布、调度或回调时终止，不能释放还会被访问的依赖。
- 显式 shutdown 应用于获得模块/持久化错误报告；析构只负责寿命安全，不是成功业务回执或恢复/物理安全证明。无协作任务永不退出时，最终排空可以一直等待，不能同时承诺有限析构时长和任意后台代码的安全释放。

### 所有权联动

最终排空期间 PersistenceService 与 SQLite 会话仍存活。真实进程测试在短停止超时后、析构已进入 drain 后分别尝试外部接管；内部任务也创建第二 Host，均须被拒绝。任务释放后仍能读取 Gateway、Task/Workflow/Script、Project/Document、资源与持久状态；完成回调之后、模块 stop 之前须已发布 Cancelled 历史。Host 销毁后原进程仍等待退出握手，此时另一进程应能接管，排除“仅进程退出才放锁”的伪证明。

C2c 的本地正确性门禁结束后形成 C2 大节点并推送现有远端；C3/C4/C6–C8 及 ST1D 三配置、故障/恢复/压力和新基线仍保留，整体未冻结。
