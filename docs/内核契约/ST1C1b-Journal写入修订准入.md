# ST1C1b Journal 写入修订准入

## 范围与当前状态

承接 C5b `b02eb9c`。只处理内核 Journal 写入与恢复的修订约束，不扩展上层模块，不新增 Project/Document 修订真值仓库。最终 Debug 308/308、专项 14/14、新增回归与扩展故障矩阵各 10 次共 100 次通过；本地检查点的完整门禁和边界见 [C1b 交付](../阶段交付/2026-09-04-ST1C1b-Journal写入修订一致性.md)，不替代 ST1D 最终签核。

旧代码仅验证重复 TransactionId 的内容、编码和摘要，新的记录直接 INSERT。新增 3 个用例在生产修改前全部失败：过期项目/文档修订被接受、非法递增或对象改变而文档修订不变被接受、已有损坏链仍可继续扩展。证据为 `build/st1c1b-red2-tests.log`（退出 8，0/3，1.82 秒）；最初的测试编译接口误用日志单独保留，不当作产品缺陷证据。

## 写入约束

1. 使用 C5 的已准入独占连接，所有持久头读取和新记录检查均发生在同一个写事务内。失败按既有 rollback/隔离规则处理，不发布应用状态、History 或成功事件。
2. 项目当前修订来自该项目最后一条 Journal，文档五个局部修订来自该文档最后一条 Journal；缺失时为零。Snapshot 必须锚定 Journal，不能赋予未记录的非零修订；Document 关闭、移除或未装载不能使项目修订归零。
3. 认证持久头的摘要及控制字段/载荷一致性，拒绝文档归属变化和前置修订不等；拒绝修订跳跃、回退和溢出。非空对象变化必须同时推进 Project 和 Document 各一次；无对象变化的低层历史材料沿用稳定/单次递增规则。这不是开放纯事件或空提交入口，ApplicationTransaction 的 EmptyCommitDenied 规则不变，修订夹具不代表合法 Gateway 命令。
4. 已存在且经过认证的同 TransactionId、同完整内容重放，返回原记录，不使用当前头错误拒绝旧回执；同 ID 不同内容仍冲突。新的 TransactionId 才可扩展当前头。
5. 新 Host 首次扩展既有 Journal 时认证已有顺序、项目/文档修订链和归属。验证成功仅保留连接内的“修订链已检查”标记，不缓存第二套修订值；每次新写仍重新读取并认证当前头。标记依赖 C5 独占和只追加协议，后端销毁即丢弃。任意原始 SQL 工具在已准入 Host 运行期间篡改历史不属于可信 Host 契约，不能据本检查宣称提供防恶意篡改保证。
6. 写入与恢复使用同一修订变化函数，避免写入放行而重启拒绝。格式版本不变；原先错误接受的非法修订记录不自动修补，也不视为合法兼容材料。
7. 文档尚无 Journal 不代表身份未占用：首笔写入还须认证已有 Catalog 和 Snapshot 的归属。复用原读路径的摘要/载荷核验，并按文档定向读取；写入复用私有 unlocked 辅助方法时持有服务锁及当前写事务，公开读接口保持原语义，不向 Host 暴露新入口。仅 Snapshot 存在却未提供数据存储时拒绝，不能凭控制列绕过核验。

首次修订链验证是 O(Journal 条数)；后续每次新写认证项目/文档两个头记录。不重复恢复全部对象或建立新的持久头表。性能影响和首次写延迟仍须纳入 C7/ST1D 新基线，不能沿用旧基线宣称无回退。

补充红灯 `build/st1c1b-owner-red-tests.log`：首笔写入归属用例的 Catalog-only 与 Snapshot-only 两个分支均失败（退出 8，0/1，0.86 秒），确认仅检查 Journal 头会遗漏尚无 Journal 的既有文档。修复同时认证首笔引用的根记录；有 Snapshot 时会读取其完整载荷，此成本只发生在该文档首次 Journal 写入。

## 验收清单

- 过期项目修订（包括新文档）、过期文档局部修订，拒绝后数据库不变且事务可继续使用；成功重试、旧回执重放和再次恢复。
- 非法后置递增、回退、对象改变但项目/文档不推进、数值边界；合法稳定/单步变化、多项目、多文档和局部作用域。
- 已有损坏链首次写入拒绝、头记录摘要或控制字段损坏、归属变化；不把仅检查 SQL 执行成功或全局序号当作修订证明。
- Kernel 执行路径拒绝过期持久头后不发布对象、修订、History、Domain Event、成功幂等回执；销毁并重启恢复后再提交成功。
- 初次链认证、项目头、文档头查询的返回错误与异常，rollback 失败后的隔离与 C5 所有权保留。
- 原有负向恢复夹具以明确原始 SQL 材料注入继续验证原错误原因，不放宽正式写入准入；原有门禁、纯生产、架构、文档和本地提交。

以上清单已取得最终代码的软件回归证据，包含首次链、Catalog、Snapshot 读取故障及 rollback 隔离。C1b 本地检查点之后继续 C2 准入/生命周期；C3–C8 和 ST1D 不因本节点通过而自动关闭。
