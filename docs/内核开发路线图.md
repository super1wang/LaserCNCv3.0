## Phase 4 交付结果

1. 已建立只读 Document/ObjectRegistry 快照、稳定对象身份和 Project/Document/Geometry/CAM/MachineContext/Environment 六域 Revision。
2. 已实现 copy-on-write ApplicationTransaction；任何写失败都会使事务中毒，rollback、放弃、冲突、空提交和 Revision 溢出不会产生部分状态。
3. commit 在独占锁内校验完整捕获 Revision，并在全部可失败材料准备完成后原子替换对象与修订状态；同一旧快照的并发提交只能有一个成功。
4. Domain Event 在 commit 前保持事务私有；只有成功回执包含不可公开构造、带提交后 Revision 和稳定顺序的 CommittedDomainEvent。
5. change set 保存 before/after，作为后续 Undo/Journal 的材料；本阶段未实现 EventBus、持久化编排或任何上层模块。
6. VS2022 x64 Debug 与 Release 均通过 54/54 CTest；Debug 全集连续 20 轮通过；Production-only Release 构建通过且未引入 Catch2。

## Phase 6 交付结果

1. 已建立版本化 TaskRegistry，以及 Pending、Ready、Running、Succeeded、Failed、CancelRequested、Cancelled、Stale 八态任务模型。
2. 已建立统一 CancellationToken、Deadline、ProgressReporter、TraceId 与 ResourceContext；进度限定在 `[0, 1]` 且只允许单调前进。
3. Scheduler 按依赖、优先级、FIFO、执行器并发度和资源可用性选择任务；高优先级资源阻塞不会阻止其他非冲突任务运行。
4. ResourceManager 对 CPU、DiskIO、GPU、OCCT、ProjectRead/ProjectWrite、MachineController、CollisionBackend 实施全有或全无获取；ProjectRead 与 ProjectWrite 映射到同一项目资源槽。
5. 文档任务由 TaskRuntime 在提交时捕获不可变 Document/Revision 快照；完成时若源修订变化，结果标记为 Stale，不能伪装成可直接应用的成功结果。
6. AppKernel 已拥有 TaskRegistry、ResourceManager、Scheduler、TaskRuntime 与注入的 ITaskExecutor，并负责冻结、启动、协作取消和有界关闭。
7. VS2022 x64 Debug 与 Release 均通过 83/83 CTest；Debug 全集连续 20 轮通过；Production-only Release 构建通过且没有 Catch2/测试目标；架构扫描通过。
8. 异步 Command 已通过同一个 CommandRuntime 完成参数 Schema、Capability、ExpectedRevision 与内存幂等检查，再由 IAsyncCommandHandler 生成只读 Task 计划；CommandRuntime 强制覆盖 Project/Document/Trace/Correlation 上下文并返回 TaskId，不允许后台 handler 获得 ApplicationTransaction。
9. 测试专用 Headless 进程使用真实 jsoncons、spdlog 与 BS::thread_pool 完成异步 Command、Task、不可变文档快照、结果 Schema、日志与关闭闭环。
10. 契约见 [`内核契约/Phase6-任务调度与资源模型.md`](内核契约/Phase6-任务调度与资源模型.md)，交付证据见 [`阶段交付/2026-09-03-Phase6-Task-Scheduler.md`](阶段交付/2026-09-03-Phase6-Task-Scheduler.md)。

## Phase 7 交付结果

1. 已定义 ITraceService/ITraceSpan/ITraceExporter、IMetricsService/IMetricsExporter 与 IDiagnosticCheck 公共端口，公共 API 不包含 OpenTelemetry 或其他第三方类型。
2. 已建立 LocalTraceService：Span 显式成功/失败/取消/陈旧终态、遗弃自动失败、父子 SpanId、内存快照、锁外 exporter 和有界记录/失败缓存。
3. 已建立 LocalMetricsService：Counter、Gauge、Histogram、稳定标签聚合、类型冲突检查、有限值校验、锁外 exporter 和有界 series/失败缓存。
4. 已建立 DiagnosticsService：组合期唯一注册、Freeze、确定性 runAll、最近报告快照；check 返回失败或抛异常均转换为 Unhealthy 报告，回调不在注册表锁内执行。
5. AppKernel 已拥有并在 Ready 边界冻结三个本地服务；Command、Query 和实际进入执行器的 Task 均生成独立 Span 和 completed/duration Metric。
6. CommandRequest、QueryRequest、TaskRequest 支持 parentSpanId；异步 Command 接受后生成的 Task 自动以 Command Span 为父节点，并保持相同 TraceId。
7. Task 的 Succeeded、Failed、Cancelled、Stale 终态映射到 Trace；调度前即取消或截止的 Task 不伪造 `task.execute` Span。
8. LogObservabilityExporter 仅依赖 ILogService，将 Span 与 Metric 映射为结构化 `trace.span`、`metric.observation` 日志；真实 spdlog JSONL 进程闭环已验证。
9. 运行时对观测调用做最外层异常隔离；exporter 返回 Error、抛异常、容量耗尽或观测实现抛异常都不得反转 Command/Query/Task 的业务结果，也不得阻断 Scheduler 后续调度。
10. VS2022 x64 Debug 与 Release 均通过 87/87 CTest；Debug 全集连续 20 轮通过，共 1740 次；Production-only Release 构建通过且没有 Catch2/测试目标；架构扫描通过。
11. 契约见 [`内核契约/Phase7-本地观测与诊断.md`](内核契约/Phase7-本地观测与诊断.md)，交付证据见 [`阶段交付/2026-09-03-Phase7-Observability.md`](阶段交付/2026-09-03-Phase7-Observability.md)。

## Phase 8 交付结果

1. 已新增 SnapshotId 与 ContentDigest 稳定身份，并定义不暴露具体算法类型的 IHashService 端口。
2. 已实现 Windows CNG SHA-256 Adapter，以 `sha256:<小写十六进制>` 形成强内容摘要；空内容、标准向量、稳定性和内容差异已测试。
3. 已建立 PersistenceService v2 migration、`state_journal` 与 `snapshot_index`：TransactionCommit/Document Snapshot 版本化序列化、SHA-256 摘要、稳定身份、重开读取和逐条完整性验证。
4. TransactionManager 以独立 commit mutex 串行化提交，先在短 Document 锁内准备不可失败回执，锁外持久化 Journal，再以无失败 swap 更新内存；持久化失败不会改变活动 Document。
5. AppKernel 已拥有 PersistenceService，配置后在 bootstrap 初始化，Ready 时冻结配置；未配置时继续支持显式的纯内存内核模式。
6. 已实现 Windows 原子文件 Snapshot Store：临时文件写入与 flush、原子发布、不可变 ID、路径穿越/大小限制，以及“先文件、后索引”的可重试写入顺序。
7. 已实现 Crash Recovery：严格全局 sequence、项目/文档 Revision 链、Snapshot 水位与摘要校验、ObjectChange before/after 重放、同项目多文档交错恢复，并在 AppKernel Ready 前原子装载 DocumentStore；历史 Event 不会重发。
8. 已建立 v3 `command_idempotency`：同步 Command 将 Journal 与幂等结果置于同一 SQLite 事务，异步 Command 将 Task 接受与幂等结果原子提交；重启重试返回原 Commit/TaskId，不调用 handler、不重发 Event。
9. 已建立 v4 `task_history`：可调度前持久接受，保存请求与 source revisions，终态不可变；未完成任务重启后显式变为 `Task.InterruptedByRestart`，终态写失败不反转业务结果且进入 Scheduler 有界失败缓存。
10. 已建立 v5 `diagnostic_history` 和 Diagnostics exporter：内存 latest 先行、SQLite 历史后写，支持重启历史/latest 查询、摘要验证及 exporter 失败隔离。
11. 已新增独立进程恢复契约：播种进程以 `_Exit` 跳过析构，恢复进程验证 Snapshot + Journal tail、原 Commit 幂等重放、历史 Event/handler 不重放、未完成 Task 中断和 Diagnostics 历史。
12. VS2022 x64 Debug 与 Release 均通过 109/109 CTest；Debug 全集连续 20 轮通过，共 2180 次；Production-only Release 构建未引入 Catch2 或测试/contract target；架构扫描通过。
13. 独立进程 `_Exit` 门禁和故障注入证明恢复 fail-closed，但跨进程共享写入、外部数据库 busy 竞争和只读部署目录不在本阶段宣称范围内。
14. 契约见 [`内核契约/Phase8-持久化与恢复.md`](内核契约/Phase8-持久化与恢复.md)，交付证据见 [`阶段交付/2026-09-03-Phase8-Persistence-Recovery.md`](阶段交付/2026-09-03-Phase8-Persistence-Recovery.md)。

Phase 8 没有实现 Workflow/Script、领域模块或产品 Host。下一阶段严格进入 Phase 9 的 Workflow Runtime 与 Script Runtime；CAD/CAM/GUI/RPC/AI 等上层能力继续延后。

## Phase 9 交付结果
