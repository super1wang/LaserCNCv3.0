# ST1C6b11 观察出口失败记录资源隔离交付

## 范围与实现

本检查点只修改 Application Kernel 的 Trace、Metrics、Diagnostics 本地服务及隔离测试进程，不增加公共 API。契约见 [C6b11](../内核契约/ST1C6b11-观察出口失败记录资源隔离.md)。

- 三服务取消每次通知的临时失败数组，逐 exporter 尝试写入有界失败窗口。
- Error 构造或失败窗口记录 OOM 被限制在当前 exporter，后续 exporter 继续调用。
- Metrics/Diagnostics 保留公开成功结果和已发布本地事实；Trace 保留完成记录且 active 为零。
- 失败窗口在资源不足时明确允许漏记，不冒充可靠审计日志。

## 红灯与焦点证据

真实 Release 红灯保留于 `build/st1c6b11-red-tests.log` 与 `build/st1c6b11-red-details.log`：三服务均跳过后续 exporter，Metrics/Diagnostics 异常逸出；本地聚合/latest 虽已形成，却与公开返回分裂。修复后隔离进程报告原有 start/完成矩阵继续通过，并新增 exporter bookkeeping 12/12：三服务 × 返回 Error/抛未知异常 × 单次/持续分配失败。

最终注册清单仍为 471 项。沿用 Foundation/Kernel/Infrastructure/架构/Headless 精确选集：Debug 216/216、Release 216/216；ASan 216 个名字各连续三次，即 648 次执行全部通过，普通输出无 AddressSanitizer 报告。扩展后的隔离探针在三轮 ASan 明细中均包含 `exporter-bookkeeping=12/12`，三套配置均在最终测试前完整重建。

纯生产 Release 构建通过，共 31 个 vcxproj，不含 test/probe/benchmark/ASan/Catch 目标及 CTestTestfile；边界检查覆盖 71 个公共头与 141 个生产源文件。公共头未修改。build 材料仅留本机、不入库。
