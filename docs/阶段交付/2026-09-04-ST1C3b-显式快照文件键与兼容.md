# ST1C3b：显式快照文件键与兼容

## 状态和范围

承接 `93e9b69`，按 [C3 契约](../内核契约/ST1C3-快照身份与存储键.md) 完善显式 SnapshotId 的物理文件映射、旧格式兼容及原子发布。实现、重复回归、全量 Debug、纯生产和定向 ASan 门禁已通过本地检查点。只覆盖内核文件适配器及其既有 AssetStore 复用链、测试和中文文档，不扩展业务模块。C3c、C4、C6–C8、C5 支持矩阵及 ST1D 仍未完成，不能宣布 Frozen。

## 实现和验收映射

| 要求 | 实现与直接证据 |
| --- | --- |
| 精确逻辑身份与路径分离 | 17 个身份夹具涵盖中文、组合/预组合 Unicode、非 BMP、大小写、路径/保留字符、设备名、点号和 128/129/1024/4096 字节；新文件名为 @ 加精确身份 SHA-256 再加 .snapshot，固定 74 字符 |
| 摘要碰撞不等于身份相同 | LCNCSN02 外层信封保存精确 ID；正确摘要位置放入其他 ID、畸形/空/超长/截断头全部拒绝读写删除；删除前校验同一打开句柄 |
| 旧格式不丢失 | 旧 ASCII 文件按实际长文件名精确大小写匹配，双向大小写夹具证明不串读、不串删；同负载幂等复用，不自动改名或迁移 |
| 无静默回退/旧状态复活 | 同一 ID 同时有新旧文件时拒绝全部操作；损坏的新信封不按旧原始负载读取，失败前后文件数量不变 |
| 目录和输入预算 | 4096 字节上界接受、4097 拒绝；负载预算不含信封，配置先检查大小溢出；原始目录尾点/空格在 absolute 转换前拒绝，本机长目录读写/删除通过 |
| 文件类型和删除归属 | 拒绝目录、非规范摘要文件名、硬链接；代码同时拒绝 reparse 属性。删除通过核验后的句柄设置删除标志，不关闭后再按路径删除 |
| 临时键竞争 | 对 CREATE_NEW 已存在最多换键尝试 8 次；实际预建 2 个占位文件后成功，预建 8 个后明确失败，所有占位内容保留；解除注入后可重试 |
| 发布/读取竞争 | 8 个并发实例同时发布两个大小写身份；实际负载回归捕获 Windows 32 共享冲突，针对打开操作加入有界重试。注入 2 次后成功、8 次后失败并保留原文件；并发胜者被读者持有的独立场景也通过 |
| 持久化和资产兼容 | 同库混合旧/新 Snapshot 的 latestSnapshot 与 recover 都核验归属；旧 LCNCAS01 资产仍能读取并保持 AssetRef，真实资产发布/引用崩溃探针校验新外层和旧内层 |

文件名摘要针对身份，不是 payload 内容地址；内容摘要仍由上层既有 Snapshot/Asset 认证链校验。数据库 storage_key 继续是逻辑 SnapshotId，不是物理文件名；单文档读取与全量恢复未新增旁路。新旧文件名空间通过旧规则禁止的 @ 分离。此兼容是新代码读取旧文件，不是旧二进制能读取新文件；回滚需匹配整套数据库/文件材料。

原生路径输入以可信存储根为前提，不声明能抵御外部写入者持续替换目录树；不支持与旧版本同时写根目录。网络共享、reparse 根、物理断电和整个文件系统支持矩阵仍由 C5/ST1D 签核。这里的重试上限是调用次数，不是硬实时毫秒期限。

## 原始失败和证据演进

- 旧实现：`build/st1c3b-red-tests.log` 为 0/5、1.28 秒、退出 8。核心映射修复后 `build/st1c3b-green-tests.log` 为 5/5、1.95 秒。
- 扩展夹具期间两次构建失败分别为测试 namespace 限定缺失及 Catch2 的 std::byte 比较链接错误，修复后继续；保留 `st1c3b-final-build.log`、`st1c3b-verified-build.log`，不将它们写为最终成功构建。
- 初次专项 `st1c3b-focused-tests.log` 为 31/31、36.98 秒，随后补了 Unicode、目录与共享冲突场景；该数字是中间证据，不代替最终扩大后的覆盖。
- `st1c3b-repeat10-tests.log` 出现并发写失败（9/10 独立项通过，14.50 秒）。单独 50 次重跑 `st1c3b-race-diagnostic-tests.log` 全绿但不关闭问题；`st1c3b-reader-race-tests.log` 的已有读者场景通过，也不是原问题的复现。
- 带并行负载的 `st1c3b-race-load-tests.log` 再次失败，明确给出 Snapshot.ReadFailed / systemCode=32；同时证明尾点/空格校验若放在 absolute 之后，已无法发现原输入。该轮 10/12 独立项通过、54.10 秒，失败目录含 `snapshot-storage-key/121960982152400-0`，均保留。
- 修正为共享冲突最多 8 次打开尝试，以及原目录组件预检后，`st1c3b-fixed-repeat30-tests.log` 的 13 个独立项各 30 次、390/390 全部通过，61.38 秒；逐测试 ID 核对运行数。不会把之前的失败轮次计入最终成功次数。

错误码 32 证明实际共享冲突，不凭日志推断具体 Windows 内部调用栈。代码仅重试这一暂态错误，拿到句柄后仍验证类型、长度与身份；持续占用不返回伪成功。所有新增失败数据库/文件在 `build/vs2022/tests/stress-contract-runs/snapshot-storage-key/` 中保留。

测试程序仅替换静态库对象，编译同一份生产源并拦截 Win32 打开/改名调用，生产不存在故障注入接口。C3a 的三进程探针改为从索引检查逻辑随机 ID，同时检查摘要文件数，避免把物理文件名误当逻辑 ID。旧资产损坏/中断探针同步命中新键及完整外层信封，不能靠制造旧格式冲突让损坏测试误绿。

ASan 实际重构建 Infrastructure tests、headless contract、close snapshot probe 及依赖，三个目标的工程均含 /fsanitize=address；使用预设的 alloc_dealloc_mismatch=1:abort_on_error=1，未启用忽略拦截失败。日志无 ASan 错误；不声称本轮运行了 ASan 全集。34 项包括 13 项新回归、既有 Snapshot/Asset/发布失败链、8 个资产真实中断场景和关闭快照三进程场景。三轮进程材料分别为 `9a83780fc4e445718200c3cd`、`2fba54ccdb5725de62d4a94b`、`2b8cd40c7a6a1e356f60bb54`，位于 `build/vs2022-asan/tests/close-snapshot-process-runs/`；每轮三个退出 0/验证标记和 24 个不重复新键均独立复核。
