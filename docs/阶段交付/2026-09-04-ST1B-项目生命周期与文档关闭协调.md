# ST1B 项目生命周期与文档关闭协调

## 范围和状态

本节点只修改 Application Kernel、测试与中文文档，不新增任何产品 CLI/RPC、GUI、CAD/CAM、Machine/Process 或 AI 模块，不引入新的第三方依赖。承接本地 ST1A `92253bc` 的 schema v9 持久组件，ST1B 本地检查点验证已通过；ST1 整体尚未验收，Kernel 1.0 未 Frozen。

## 实现

- AppKernel 唯一持有 ProjectRuntime；配置期 addProject、运行期 create/open/close/lifecycle/list 支持独立空项目。Closed 项目仍保留稳定身份，无任意删除持久目录的入口。
- 原配置期 addDocument 显式声明所属项目；运行期文档 create/attach/open 不再凭任意 ProjectId 自动建立项目。
- 父项目 Open 准入租约覆盖文档生命周期和既有 Document activity，关闭封住准入后检查全部子文档，再经私有协调路径逐个持久关闭；Host 无 skipPolicy、start/stop 或租约构造权限。
- 关闭失败保留真实部分结果，项目进入 Failed。先前已成功关闭的子文档不回滚为 Open；后续失败也不伪报整个项目 Closed。项目重新打开不自动打开文档。
- 一次性迁移只承接已验证旧文档根；迁移后每次启动仍核对项目目录，缺失根不通过显式配置自动修复。配置不能暗中重开持久 Closed/Failed 项目。
- 空项目的 Opening/Closing 中断读作 Failed 且保留原始证据；不可用项目下有持久 Open 文档时拒绝启动，不能把父子状态不一致解释为恢复成功。
- 文档及项目租约先分配、后在锁内确认状态并增加计数；文档活动释放后才释放父项目活动。文档身份可能在准入间隙重新绑定时，进入最终文档锁后再次核对所属项目。
