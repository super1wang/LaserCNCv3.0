# ST1C6b9 Trace 完成资源失败原子性交付

## 范围与实现

本检查点只修改 Application Kernel 的 Trace 内存服务与隔离测试进程，不增加公共 API，不涉及 GUI、CAD、CAM、设备、网络或产品 CLI。契约见 [ST1C6b9](../内核契约/ST1C6b9-Trace完成资源失败原子性.md)。

- 句柄新增对共享 Core 的内部持有，正常 completion 失败后直接幂等删除其活动 SpanId。
- 显式 `end` 的非法终态诊断失败、完成记录保留失败和 exporter 快照失败均不能留下活动孤儿。
- 未结束句柄析构构造 abandoned 诊断失败时采用同一删除路径。
- 资源失败后是否存在完成记录仍是尽力语义；不把 `noexcept` 写成记录必达。

## 红灯与最终门禁

Release 红灯由真实旧实现产生并保留于 `build/st1c6b9-red-tests.log` 和 `build/st1c6b9-red-details.log`：隔离测试失败，多个完成分配点出现活动孤儿、析构无法补偿、身份重试与保留窗口不一致及最终清理失败。修复后焦点探针报告 startSpan 14 点、合法完成 11 点、非法完成 31 点、abandoned 28 点全部通过，且完成三条路径的每个点同时覆盖一次性和持续分配失败。

最终注册清单为 470 项。沿用 C6b8 的 Foundation/Kernel/Infrastructure/架构/Headless 精确选集，仅将扩展后的探针名称更新为 `integration.trace_allocation_atomicity`：Debug 215/215、Release 215/215；ASan 215 个名字各连续三次，即 645 次执行全部通过，普通输出无 AddressSanitizer 报告。ASan 三轮明细均包含 `start=14 completion-valid=11 completion-invalid=31 completion-abandoned=28` 标记。三套配置在测试前均完整重建。

纯生产 Release 构建通过，共 31 个 vcxproj，不含 test/probe/benchmark/ASan/Catch 目标及 CTestTestfile；边界检查覆盖 71 个公共头与 141 个生产源文件。公共头未修改。Debug 的探针输出仅代表链接/启动 smoke；Release 与 ASan 才是分配故障证据。build 材料仅保留本机、不入库。
