# ST1C3a：自动关闭快照身份

## 状态与范围

承接 `b010777`，按 [C3 契约](../内核契约/ST1C3-快照身份与存储键.md) 修复 DocumentId 与自动关闭快照键的耦合，形成本地检查点。最终 Debug、重复回归、纯生产及定向 ASan 门禁通过。仅修改内核、测试与中文文档，不扩展上层模块。C3b/c 和 C4/C6–C8/ST1D 仍未完成，Kernel 不处于 Frozen 状态。

## 实现与证据

| 要求 | 实现及直接验证 |
| --- | --- |
| 文档身份不受文件名限制 | 生成器不接收 DocumentId；13 个夹具覆盖中文、大小写、路径/保留字符、CON/NUL、点号及 96/128/129/1024 字节长度；每个夹具跨两个 Host 反复关闭与恢复，核验精确文档和项目身份 |
| 不依赖时间或进程计数 | 每次取 256 位随机量，小写十六进制编码为固定 82 字节；没有墙钟、PID、递增计数或静态初始化状态参与命名 |
| 随机源失败 | 私有生成器接缝覆盖全零、标准和非标准异常；返回 Snapshot.IdentityGenerationFailed，不回退到时间键。Host 无随机注入新接口 |
| 随机碰撞不覆盖 | 固定相同随机量，给大小写不同的两个 DocumentId 捕获快照；第二次返回 Persistence.SnapshotIdentityConflict，首份负载保持不变，第二文档没有快照；同身份同负载仍可幂等重复 |
| 真实进程重启 | 同一数据库顺序启动三进程，每进程四个文档各关闭两次；文档包含同时存在的大小写对、中文路径字符、1024 字节 ID。驱动核验每进程 8 个新键、全程 24 个唯一键及完整退出/成功标记 |
| 旧快照兼容 | 未改 Snapshot 负载、索引 schema、storage_key 等值验证、文件读取/删除或迁移路径；复跑原有不可变捕获、读取、重复、冲突、恢复与删除回归 |

`snapshot.close.v2.` 是命名版本，不是负载格式版本；继续写 version 3，原有 1/2/3 读取能力不变。随机性降低碰撞概率但不证明绝对唯一，也不赋予安全权限。created_at_ms 及其排序未修改，未调整操作系统时钟；其语义和回拨下恢复完整性由 C3c 继续核验。矩阵通过不等于任意 ID、非法 UTF-8 或任意目录长度均受支持。

## 原始失败与修正

- `build/st1c3a-red-build.log` 退出 0。旧实现的 `build/st1c3a-red-tests.log` 为 0/2、47.68 秒、退出 8；13 个身份夹具中 7 个关闭失败，另一用例确认旧 ID 含 DocumentId 且不满足独立格式。
- `build/st1c3a-green-build.log` 为开发期失败：Catch2 INFO 宏中三目表达式缺少括号，触发测试源编译错误；已修正，不能将此记录描述成生产生成器编译失败。
- 身份唯一性断言统计不可变文件键，不把时间排序的 latestSnapshot 当作插入序号。读取仍核验精确文档/项目；时间排序的完整契约没有因此被删去，而是留在 C3c。
- 新测试数据库、快照和独立进程日志均保留，不清理失败材料。单元材料位于 `build/vs2022/tests/stress-contract-runs/close-snapshot-identity/`，进程材料位于 `build/vs2022/tests/close-snapshot-process-runs/`。

专项三进程材料 `b5369ad9bea7e0eeb534348e` 中三个日志均 exit=0、8 个 new 键且有成功标记。新增 4 个 Catch2 用例加 1 个真实进程门禁；重复次数不得当作独立用例数。

Debug 的专项、全量及重复共保留 5 组完整进程目录；每组逐一复核 3 个日志、正常退出及 24 个唯一键。ASan 三组目录为 `5f46bafdee46dcbdb3ed30f7`、`73dc79e089adc4d54c6f2d27`、`db3a59f187815df75044c99f`，同样全部完整，位于 `build/vs2022-asan/tests/close-snapshot-process-runs/`。仅重构建新探针和其生产依赖，核对 Kernel、Infrastructure、新探针的 `/fsanitize=address`；不宣称旧 ASan 单元测试产物已重建或当前 ASan 全集已通过。

源码复核发现边界脚本未扫描 src 私有 h/hpp，已在 [剩余计划](../内核契约/ST1C-补充审计与剩余执行计划.md) 的 C8 登记补扫与负向探针。本次新私有头仅依赖标准库与 Kernel/Foundation；71/139 不是对该私有头的自动扫描成绩。
