# ST1C2c1：停止确认与失败重试

## 状态与变更

承接 `5259978`，按 [C2c 子节点契约](../内核契约/ST1C2c-停止确认与析构依赖.md) 推进内核停止链。最终门禁通过，形成本地检查点；本节点不关闭 C2c2 或整体冻结。

- Scheduler 将停止请求与执行器确认分离。已配置未启动的执行器仍须停止；失败/异常后能真实重试，不因为 started 提前清除而报告成功。
- AppKernel 配置期和运行期统一经 Scheduler；执行器未确认时保持 Stopping、保留模块。负超时在状态/准入变更前拒绝，无执行器同样适用。
- 永久关闭 Scheduler 接纳，停止后不能再 start/configure；成功后顺序重复调用幂等。并发/回调重入停止返回明确冲突，不等待自身或重复停止执行器。
- 成功前等待运行任务、提交调度和终态发布结束，再取得执行器确认；异常转换为 Task.ExecutorShutdownFailed，原始错误 Result 保留。极大正超时按饱和截止点处理。
- 公开签名及持久格式不变；补充 ITaskExecutor 停止确认语义与 Scheduler 超时边界注释。没有新增上层模块或第三方依赖。

旧生产代码上，`build/st1c2c1-red-build.log` 构建成功，`build/st1c2c1-red-tests.log` 为 0/4、退出 8、0.34 秒。四个实际失败覆盖：Host 停止错误/异常后的提前成功和模块撤销、独立 Scheduler 未启动/失败重试、停止后重启，以及负超时关闭入口。红灯是生产行为差异，不是刻意制造编译失败。
