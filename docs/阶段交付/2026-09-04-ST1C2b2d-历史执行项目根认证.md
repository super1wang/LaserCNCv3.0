## 缺陷与实现

原 AppKernel 与迁移集合仅纳入 DocumentCatalog、Journal 和 Snapshot 根。Project-only Task/Effect 没有文档时，项目被遗漏；迁移已完成后，其缺失项目也未被拒绝。

1. PersistenceService 私有枚举执行历史身份，复用既有 Task/Effect 历史读取器核验载荷摘要、索引、状态和终态材料，再取得来自同一次已校验读取的请求/签名。公共历史查询契约不变，Host 无法调用内部归属枚举或 unlocked 读取器。
2. 核验 Task 的 lasercnc.task-acceptance v1 与 Effect 的 lasercnc.external-effect-signature v1；严格区分显式 Null 和缺失/非法身份字段。Effect 还核验命令、会话、请求/解析版本、版本解析模式、外部副作用分类、策略一致性及相关帧字段。不据此解释业务 input/arguments，也不授予执行能力。
3. ProjectId 为 Null 且 DocumentId 为 Null 的历史不产生项目；存在 DocumentId 则必须有合法 ProjectId，并匹配已校验目录（含 Removed 墓碑）或恢复镜像的真实所有者。缺失/错误文档归属拒绝，不从历史构造文档。
4. AppKernel 在安装目录前认证全部执行根。pending 迁移的写事务再次认证执行历史，和原文档来源组成完整去重项目集合，严格比对调用方已验证集合；缺少、多余、重复项目均拒绝。迁移完成后仍在启动时核对根是否存在，缺根拒绝，不自动修复或重置已有 Closed 项目。
5. 接受但未完成的 Task、未知副作用继续遵循既有初始化中断标记规则；只读历史保留真实终态和结果，不启动 Handler、任务或副作用重放。历史认证失败不部分安装运行目录；迁移写事务失败保留 pending 状态，无部分项目条目，新 Host 可干净重试。

这里的“认证”指既有摘要、格式、结构及索引/归属一致性验证，不是密钥签名，不宣称抵抗同时有权重写载荷和摘要的攻击者。可信存储和单活动 Host 边界保持不变。

兼容性对照以远端审计基线 `2bb2e70` 的真实编码为依据：其 TaskRuntime 已拒绝缺少 ProjectId 的文档任务，Effect 帧已显式编码 projectId/documentId（可为 Null）及上述版本、会话和策略字段。本节点不把独立 PersistenceService 能写入的任意测试载荷，等同于旧 AppKernel 可合法产生的历史。资源/Guard 元素及业务参数不在本轮归属解码中重新执行 Schema 校验，不宣称完整请求可重放。
