## 实现与验收映射

| 要求 | 实现和直接证据 |
| --- | --- |
| 非协作任务超时不等于结束 | 普通 shutdown 保持 Stopping；Host 析构在各 Runtime/模块/持久化之前执行强制 drain，执行器销毁后才释放依赖 |
| 错误/异常后的最终析构保证 | ITaskExecutor 新增纯虚 drainForDestruction 与 isCurrentWorkerThread；持续失败及抛异常替身覆盖配置期/运行期；强制排空可成功，即使普通 shutdown 始终返回失败 |
| 自等待/自销毁 | 任务/调度/完成/持久回调线程范围及执行器工作线程检查；同步执行器、自任务 wait/shutdown、终态观察回调均拒绝；Host/执行器工作线程自销毁用独立进程确定退出验证 |
| Configuring/Failed/Stopped | 五场景模块矩阵：未启动、Ready、启动失败、模块停止失败、执行器错误后的 Stopping；复用原有重复成功停止回归，确认错误不会重复撤销模块 |
| 真实依赖存续与所有权 | 独立进程中短停止超时、进入最终 drain、任务释放、Host 已销毁而进程尚存活四阶段握手；同进程/跨进程拒绝及之后接管；任务与完成回调读取真实 Runtime/资源/持久状态 |
| 停止顺序 | 工作和观察完成、资源释放、持久 Cancelled 历史发布后才调用见证模块 stop；新 Host 可恢复并接管 |
| 独立组件线程模型 | 公共头和契约明确所有者负责串行装配/提交激活/停止与寿命；Scheduler 对残留任务/回调拒绝析构，不替借用执行器隐式 join |

新增接口要求所有实现显式适配；现有线程池、同步和排队测试替身已适配。未改变持久格式，不宣称旧执行器实现源码零改动或 C++ ABI 兼容。最终屏障不承诺硬超时；无法安全返回时终止进程，不能在失败后假装依赖可释放。

## 开发期原始证据

- `build/st1c2c2-red-build.log` 退出 0；旧生产代码上 `build/st1c2c2-red-tests.log` 0/2、退出 8、1.19 秒：任务内停止关闭 Host 准入、持续错误/异常执行器缺少最终 drain。第二项是最终端口/顺序缺口证据，不冒充已捕获堆越界。
- 核心修复后 `build/st1c2c2-green-tests.log` 12/12、0.60 秒。之后增加配置/失败矩阵、同步执行器和真实进程。
- 首次真实进程测试 16.78 秒失败，诊断重跑 16.89 秒仍未收到 destroyed。记录保存于 `build/st1c2c2-process*-tests.log` 和 `build/vs2022/tests/final-drain-process-runs/<run>/`。改为外部文件门闩后，原始 holder 明确记录 exit=4 / invalid handshake；最终日志证实 stdin-bom-normalized。根因是测试未处理 PowerShell 的输入 BOM，异常清理提前进入析构，不是“已发放门闩却仍发生生产 drain 死锁”。输入规范化沿用既有所有权探针做法；文件门闩保留，消除清理时额外读 stdin 的线程。
- BOM 修复后 holder 已正常完成，但 self-host 负例仍返回兜底 7；直接诊断记录 self-host-delete=1、未返回销毁。将确定性终止处理器显式设置在实际工作线程后，`build/st1c2c2-worker-terminate-tests.log` 1/1、2.12 秒通过。记录本机实际行为，不将主线程处理器设置当作工作线程生效证据；生产不依赖测试处理器。最终负例要求对应分支标记、退出 91 且在 3 秒进程上限内结束，不能用超时或其他异常退出代替。
- 中间矩阵 `build/st1c2c2-matrix-tests.log` 为 14/15，唯一失败是当时未收口的进程负例；不覆盖或删除该日志。
- 复核进程日志发现仅有 5 个子检查，而不是预期 6 个。Windows PowerShell 5 的 ParseFile 语法树证实：无 BOM 的中文脚本漏掉了销毁后跨进程接管调用。已为新脚本显式使用 UTF-8 BOM，复核语法树得到 6 个 Check-Probe；另增加六次执行计数与原 holder 尚存活断言。此前进程绿灯不支持跨进程销毁后接管结论，最终以修正后的矩阵及独立 acquired 日志为准。C8 须增加脚本编码/解析与预期子步骤完整性审计。
