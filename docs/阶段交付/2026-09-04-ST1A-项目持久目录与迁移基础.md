# ST1A 项目持久目录与迁移基础

## 结论

ST1A 持久组件检查点通过并提交本地；ST1 整体未验收，Kernel 未冻结。本次依据原规划明确的 Project 生命周期要求继续补齐，不再把先前范围问询作为阻塞。没有实现 Project UI 或任何上层模块。

## 实现

- schema v9 新增 project_catalog 与一次性迁移标记；新项目可以没有文档。
- 状态为 Closed/Opening/Open/Closing/Failed；格式为 lasercnc.project-lifecycle.v1，摘要绑定身份、状态和时间。未知枚举、错误格式、字段/摘要/控制列不一致与超范围时间拒绝。
- Opening/Closing 读取为 Failed + interruptedTransition，不隐式回写或猜测完成。
- 旧项目根身份必须由已验证恢复结果提供，并与 Journal/Snapshot/Document catalog 的完整所属集合一致；全部目录行与完成标记在同一事务提交，失败无部分目录。已经完成的迁移不再增加身份。
- v9 的表或标记丢失时初始化失败，不重建为一个看似正常的空项目目录。
- AppKernel 的 const Persistence 观察边界不变；普通和 const Host 都不能调用项目保存/迁移，测试夹具独立拥有连接。

## 证据

新增 11 个 Project 持久组件用例，连同既有“拒绝未来 schema”用例构成 12 项专项。包含空项目重连、五状态/未知状态、十类篡改、v8 升级、Journal-only/Snapshot-only 身份来源、完整集合校验及重复迁移。四项故障矩阵共 38 个明确场景，涵盖数据库、摘要、序列化、读取和回滚隔离。

| 门禁 | 结果 |
| --- | --- |
| Debug 全集 | 275/275，326.37 秒 |
| 专项重复 | 12 项各 3 次，共 36 次，70.14 秒 |
| 纯生产 Release | 31 工程；无测试/契约/Benchmark/ASan 工程、插桩配置或 CTest 文件 |
| 架构 | 69 公共头、134 生产源；正负例通过 |

日志、SHA-256 和首次测试链接问题见 [ST1 契约](../内核契约/ST1-独立项目生命周期收口.md)。首次失败没有覆盖或删除，未修改第三方库以规避错误；错误码断言改为仓库既有的 std::string 格式。
