# ST1C6b12 观察出口快照无分配发布交付

## 范围与实现

本检查点只修改 Application Kernel 的 Trace、Metrics、Diagnostics 本地服务及隔离测试进程，不增加公共 API。契约见 [C6b12](../内核契约/ST1C6b12-观察出口快照无分配发布.md)。

- 三服务在本地事实发布点只冻结 exporter 数量，不再复制完整共享所有者向量。
- 通知时逐项锁内取得一个共享所有者、锁外调用；注册表只追加，因而保持发布时前缀快照，迟到或重入新增的 exporter 不进入本批。
- C6b11 的逐出口失败记录隔离保持；Diagnostics 的同 ID 租约在 latest 与数量发布后、出口调用前释放。
- 公共头、错误码、DTO、持久格式和依赖均未变化。

## 红灯与焦点证据

真实 Release 红灯保留于 `build/st1c6b12-red-tests.log` 与 `build/st1c6b12-red-details.log`：Trace 六条场景均在完成记录已保留后没有把目标完成通知给既有出口，Diagnostics 在 latest 已发布后仍抛出并跳过两个出口。Metrics 的旧向量复制发生在聚合提交前，因此对应注入保持无聚合、无出口的强预发布原子性。

修复后 `integration.trace_allocation_atomicity` 通过，隔离进程报告 `start=14 completion-valid=10 completion-invalid=30 completion-abandoned=27 exporter-bookkeeping=12/12 snapshot-metrics=9 snapshot-diagnostics=2 snapshot-membership=3/3 retry-and-state=passed`。每条 Metrics/Diagnostics 分配路径均核对注入是否命中、本地事实是否存在、公开结果和两个出口调用次数；Trace 保持身份重试与有界完成窗口一致。3/3 成员回归还证明出口回调中追加的出口不进入当前批、会进入下一批。

## 最终门禁

最终注册清单仍为 471 项。沿用 Foundation/Kernel/Infrastructure/架构/Headless 精确选集：Debug 216/216、Release 216/216；ASan 216 个名字各连续三次，即 648 次执行全部通过，普通输出无 AddressSanitizer 报告。扩展后的隔离探针在三轮 ASan 明细中均包含 `snapshot-metrics=9 snapshot-diagnostics=2 snapshot-membership=3/3`，三套配置均在最终测试前完整重建。
