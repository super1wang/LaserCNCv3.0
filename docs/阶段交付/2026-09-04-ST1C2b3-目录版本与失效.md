# ST1C2b3：目录版本与失效

## 状态与实现

承接 `4f7959d`，按 [C2b3 契约](../内核契约/ST1C2b3-目录版本与失效.md) 实现 Project/Document 生命周期目录失效。本节点最终门禁通过，C2b1–3 形成本地实现检查点；不宣称 ST1D 或整个内核已冻结。只修改内核及测试/中文文档，未扩展上层模块。

新增两个 Runtime 的 catalog 可选项目作用域快照，以及公共 CatalogVersion/目录 DTO。版本和值在同一锁下复制；条目不包含易变的活动计数，不把业务提交当作目录变更。epoch 使用随机实例命名空间，不使用墙钟；每个 Runtime/新 Host 独立。删除保留作用域计数，中间态、失败、回退和恢复安装均失效，饱和后停止发布令牌而非回绕。计数对象私有，Host 负向编译断言禁止直接改写。

保持旧 list/lifecycle 接口、生命周期唯一准入、业务 Revision 和持久格式不变。新增构造分配/随机源可能抛异常，取消两个 Runtime 构造的 noexcept；须登记 C6，不宣称跨工具链 ABI。目录令牌不是权限、租约或原子写前置条件；不同 Runtime 的两个目录结果不构成跨目录原子快照。

## 先失败与开发期材料

- `build/st1c2b3-red-build.log` 编译成功；`build/st1c2b3-red-tests.log` 为 0/2、退出 8、0.24 秒：当前缺少版本化目录快照契约，不能完成 ABA 验收。这是契约缺失证据，不冒充实际已捕获读写竞争。
- 首次扩展测试编译用了不存在的 CapabilityService::grant，改为既有 replace；之后 7/8 通过，剩余 Query 测试遗漏 ExecutionServices，诊断为 Runtime.ExecutionServicesNotConfigured。补齐既有校验/日志装配后 8/8、9.07 秒。构建及测试错误均保留，不作为生产红灯。
- `build/st1c2b3-matrix-build.log` 曾出现 history_runtime_tests.obj 的 LNK1163（COMDAT 0x6A9F）。该对象有 28,260 节、14,194,644 字节，不根据一次失败推定达到 COFF 上限或工具链根因。保留原对象为 `build/st1c2b3-history-invalid-comdat.obj`；只添加测试说明后定向重编译，生产编译选项未改，`build/st1c2b3-matrix-recompiled-build.log` 退出 0。该事件单独记载，不用“无失败”掩盖。
- 中间专项依次 11/11（11.17 秒）、12/12（8.50 秒）；随后增加真实进程探针，最终以 13 项门禁为准。
