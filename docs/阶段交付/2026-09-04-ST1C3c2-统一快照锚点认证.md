# ST1C3c2：统一快照锚点认证

## 状态和范围

基线 `05d53fb`。本节点修复公开 latestSnapshot 与完整 recover 的认证差异，仅修改内核持久化生产源、测试及中文文档；不增加上层模块或公开接口，不修改数据库 schema、Snapshot 负载版本、文件信封。Debug 全集、专项重复、统一 C3 ASan 及纯生产门禁通过，C3a/b/c 形成本次正确性大节点；整体 Frozen 仍等待 C4、C5 支持矩阵、C6–C8 和 ST1D。

## 复现与实现

1. 原代码在四种静态损坏材料下 latestSnapshot 都返回成功，而 recover 拒绝：水位超出 Journal、倒退至 0、移到同项目另一文档提交之后却保留旧项目修订、Journal payload 损坏。`st1c3c2-red-tests.log` 0/1、四个失败断言、2.81 秒、退出 8。
2. 仅修订锚点共用后，新增“篡改/遗漏对象并重新计算摘要”场景证明两个入口都可能接受与 Journal 矛盾的状态。`st1c3c2-content-red-tests.log` 0/1、1.11 秒、退出 8；这不是普通文件摘要损坏。
3. 扩展到水位 0 的旧快照被改到另一项目，后续 Journal 仍携带原归属时，公开读取仍有遗漏。`st1c3c2-expanded-tests.log` 3/4、4.60 秒、退出 8，失败项只在 latestSnapshot 返回成功；恢复已拒绝。

现在两个入口使用 recovery.cpp 中同一 decodeSnapshot、validateJournalHistory 和 validateSnapshotAnchor。共用全局连续序号、Journal 摘要/负载/修订变化、项目和文档修订链、完整历史归属，以及所选水位对应的修订认证。公开读取不再维护另一份快照解码/锚点实现，不调用 recover，不安装 DocumentStore、History 或发布事件；原写入序列与锁归属不变。

锚点还校验已入 Journal 对象的最终状态：创建、更新、删除使用既有 applyChanges 和精确 ObjectRecord 比较，拒绝内容/类型/版本/资产引用不一致、遗漏或删除后复活，错误为 `Persistence.SnapshotContentMismatch`。仅对目标文档锚点之前的已触及对象构造校验状态，不重放其他文档的完整对象图。

## 边界与后续成本

- Journal 没有触及的历史基线不能从 Journal 推断为“必须为空”；现有 Snapshot-only/旧格式兼容保留。该范围不获得新的导入或执行授权；C4 仍须关闭公开 attach(DocumentImage)，把可信导入纳入唯一事务/认证持久链。
- 无快照返回 nullopt，不表示整个数据库可恢复；有快照则验证完整 Journal 链及其锚点。latestSnapshot 返回捕获时的状态，不代替后续 Journal 的最终状态安装。
- 同水位时间排序不保证最后一次 capture 的身份；时间回拨不能越过更高 Journal 水位。失败不回落到旧快照，也不修复/删除损坏材料。
- 公开读取持有现有服务互斥锁并依赖单 Host 独占；内部首笔 Journal 归属检查可在既有事务中调用，不新开嵌套事务。外部 SQL 同时改写不属于受支持写入模式。
- 公开读取现在需要完整 Journal 解码与修订链校验；目标文档还需遍历锚点前的已触及对象。C7 必须测量新增读取/内存成本与恢复放大，不将“不安装对象”误写成“没有对象复制”；本节点不宣布容量或延迟上限已获准入。
- C6 登记读取保证增强、共用解码带来的错误分类及新内容矛盾错误；不承诺跨工具链 C++ ABI。
- 这里的“认证”指现有摘要、格式、归属和跨材料一致性校验，不是抵御攻击者同时重写全部 Journal/快照及其摘要的密码学来源证明；可信存储根、单 Host 与物理支持边界仍按 C5/ST1D 处理。

## 验证记录

新增四个独立锚点用例，含四种水位/Journal 损坏、两种对象矛盾、删除复活和跨水位归属。每种材料还销毁持久服务并启动新 AppKernel，核对原始失败原因、Failed 状态、运行期不接纳、目标文档未安装。C3c1 六项排序/历史身份测试保留并一并回归。

中间共用实现曾通过 8/8、15.06 秒，但后续归属扩展复现仍失败，不将该中间绿灯当作最终签核。最终全目标构建过程中一次 LNK1236 COFF 错误，下一次重链成功；该现象不推断为已知编译器缺陷。另一次新增测试 string_view 诊断导致 Catch2 StringMaker LNK2019，改为 std::string 比较后重编译；保留 `st1c3c2-final-build.log` 与 `st1c3c2-verified-build.log`。已显式触发相关生产源重新编译，`st1c3c2-completed-build.log` 全目标 Debug 构建退出 0；不是 clean-first 全目录重构建。
