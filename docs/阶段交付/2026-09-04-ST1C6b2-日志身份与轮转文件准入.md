# ST1C6b2：日志身份与轮转文件准入

## 当前范围

基线 `e06add6`，仅内核 Infrastructure、测试及中文文档。实现 [日志文件身份契约](../内核契约/ST1C6b2-日志文件身份与轮转准入.md)：同时预检 base/轮转名称及现有物理文件身份，保留合法大小写敏感文件，拒绝未知元数据。最终 Debug 426/426、定向 20 项各 3 次、ASan 68 项各 3 次、探针另 3/3 及纯生产/边界通过。本节点先本地提交，完整 C6 大节点完成后再推送远端，整体未 Frozen。

- 改为在本轮新建空子目录创建专属 Owner Rights ACL，再请求需要的目录权限。`st1c6b2-case-owned-tests.log`：两种正例通过；之后扩展到未创建子目录，`st1c6b2-expanded-tests.log` 为 7/7。没有提升宿主权限、修改父目录 ACL 或更改整个卷的大小写规则。

- 将已知非文件目标预检与后续共享失败拆成独立测试，后者先实际证明 metadata 句柄可读，再核对 InitializeFailed、原内容保持和先创建的空文件。`st1c6b2-verified-focused-tests.log`：18 项各 3 次，54/54、5.12 秒、退出 0。失败现场全部保留，不清洗或覆盖为绿灯。
- 再复核发现本轮实现对中间目录手工裁剪、提取父目录后重新套用末组件规则的风险。最初新增两项夹具错误地单独比较目录名，`st1c6b2-normalization-red-tests.log` 的 0/2 是夹具断言失败；改为目录内真实 sentinel 文件锚点后，`st1c6b2-normalization-anchored-red-tests.log` 得到生产行为 0/2、0.18 秒：同一真实目录被漏判，两个真实不同目录被误判。保留完整区别，不合并宣称为一次红灯。

## 实现与覆盖

私有实现按既有边界拆分：logging/spdlog/log_file_identity.cpp/hpp 负责 backend 的 calc_filename 与集合冲突；persistence/filesystem/windows/log_file_identity.cpp/hpp 负责原生路径/目录策略/文件身份读取，双方均不进入公共 API。普通 Win32 名称规范化与扩展路径分开；以现存目录文件 ID 和大小写策略定位未来名字，以卷号/128 位 file ID 检查已存在的 base、轮转及硬链接。预检仅 OPEN_EXISTING，不创建或改名；冲突返回 InvalidOptions，检查失败由 create 映射 InitializeFailed。原始单路径文本比较不再是唯一防线。

新增 11 个 CTest、36 个内部场景。两个合法大小写敏感输出实际写入人工/JSONL 记录及轮转文件，普通新目录和真实尾随字符目录也实际往返；既有目标的内容保持与新目标没有创建输出分别断言。超出锁定库的 200000 保留数提前拒绝，公开 Options/方法签名不变。

只对稳定可信配置根的静态别名准入负责，不提供整个日志寿命的文件锁、跨实例互斥、恶意链接替换防护或任意 I/O 原子回滚。极端保留数的 O(N log N) 临时集合与逐目标元数据查询成本登记到 C7，不把本轮默认/小保留数回归写成最大容量认证。

## 复现方式与材料

沿用既有 Windows x64、MSVC 19.44.35216.0、Windows SDK 10.0.26100.0、CMake 3.29.3 和锁定依赖。本机大小写属性/目录符号链接需要真实可用能力，夹具设置失败不得冒充通过或静默跳过。各重型构建阶段串行使用 --parallel 1 /nodeReuse:false；同构建树的 CTest 清单采集、执行、明细复制串行，禁止在活动 CTest 中另开 show-only。

```powershell
cmake --build --preset vs2022-debug --parallel 1 -- /nodeReuse:false
$focus = 'Logging identity|Logging path|Logging malformed UTF16|SpdlogLogService|File adapters|File path rejection'
ctest --preset vs2022-debug --show-only=json-v1 -R $focus
ctest --preset vs2022-debug -j 2 --repeat until-fail:3 -V -R $focus
ctest --preset vs2022-debug --show-only=json-v1
ctest --preset vs2022-debug -j 4 -V
cmake --build build/production-only --config Release --parallel 1 -- /nodeReuse:false
cmake --build --preset vs2022-asan --parallel 1 -- /nodeReuse:false
$scope = 'Filesystem|Snapshot storage|Snapshot publication|Asset |AssetStore|File adapters|File path rejection|Logging identity|Logging path|Logging malformed UTF16|SpdlogLogService|SqlitePersistenceBackend|SQLite Host session|Offline storage|integration.kernel_crash_(snapshot|asset)|integration.close_snapshot_identity_restart'
ctest --preset vs2022-asan --show-only=json-v1 -R $scope
ctest --preset vs2022-asan -j 2 --repeat until-fail:3 -V -R $scope
ctest --preset vs2022-asan --show-only=json-v1 -R '^integration.kernel_asan_probe_'
ctest --preset vs2022-asan -j 1 -V -R '^integration.kernel_asan_probe_'
cmake -DLCNC_SOURCE_ROOT=J:/Code/LaserCNCv3.0 -P cmake/VerifyKernelBoundaries.cmake
```

实际流水线逐命令检查退出码，测试结束即复制 LastTest.log。上面按顺序展示命令，不表示忽略失败继续；生成物、临时文件、含失败材料的测试根保留在本地 build，不提交入 Git。
