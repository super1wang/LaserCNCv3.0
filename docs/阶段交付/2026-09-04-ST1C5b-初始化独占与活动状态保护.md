# ST1C5b 初始化独占与活动状态保护

## 范围与结论

基于 C5a `adbd91d`，只改动内核持久化准入、诊断与测试设施。将单活动 Host 从适配器能力接入独立 PersistenceService 和 AppKernel 的强制初始化链，早于 schema、命令 claim、Task 和副作用中断恢复。最终 Debug 全集、专项、新增门禁重复和纯生产/架构均通过，形成 C5b 本地检查点；本记录不是 C5 或 Kernel 1.0 冻结签核。

实现与完整边界见 [C5 契约](../内核契约/ST1C5-持久化Host独占与耐久准入.md)，后续顺序见 [ST1C 执行计划](../内核契约/ST1C-补充审计与剩余执行计划.md)。

## 实现

- initialize 在任何初始化 SQL 之前取得会话；错误/异常不进入事务或 schema SQL。成功后的重复 initialize 只重新核验准入，不再次执行中断状态恢复。
- 同一数据库的第二服务/Kernel 被拒绝，正在执行的命令 claim 保持 pending，第一 Kernel 仍正常提交。初始化失败不充当接管许可。
- 策略漂移或回滚隔离后保持文件所有权，拒绝旧服务重新启用，后端销毁后才允许新服务接管。未新增提前 release 或绕过开关。
- sessionStatus 只读展示申请/成功证明状态、ready 与最近成功配置，明确缓存证据不是实时健康值；Benchmark 改为准入后采集实际 SQLite 配置。
- 迁移原有双 Host 夹具：正常快照走 close/open；中断材料由前任销毁后的顺序 Host 播种；负向对象版本材料用明确原始 SQL 破坏注入。保留 Snapshot 故障矩阵和崩溃边界断言；项目恢复负向用例增加根错误码检查，不能因 Host 冲突而假通过。

## 后续与支持边界

- C1b 仍需在同一写事务内检查项目/文档前置修订、后置变化与已验证同 TransactionId 重放，独占锁不能代替修订检查。当前 append 已具备事务及同 ID 内容核对，但新记录路径尚无持久头修订检查。
- C2c 的全局 shutdown/drain/析构生命周期仍待审计；本节点不把停止超时当作后台执行结束，也不提供提前释放 API。
- 本机 NTFS 软件门禁不等于物理断电保证；ReFS 与非本地卷拒绝的真实环境尚未验证。支持矩阵必须保留这个差别。
- Release/ASan 全集、最终连续压力、正式新性能基线及冻结重新签核由 C7/ST1D 完成。旧 F5C 的性能结果不覆盖 EXTRA 配置和新初始化路径。
- 本节点提交本地；完整正确性与认证大节点再推送远端，本轮只读核验远端 main 仍为 `2bb2e70e7a6a78af9ee0ccaa379384e22fcf8ed0`。不新增 GUI、产品 CLI/RPC、CAD/CAM、Machine/Process 或 AI 模块。
