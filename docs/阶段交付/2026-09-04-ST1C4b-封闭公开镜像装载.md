# ST1C4b：封闭公开镜像装载

## 状态与范围

基线 `13fd2e7`，承接 [C4 契约](../内核契约/ST1C4-可信装载与事务导入.md)。公开镜像入口与夹具迁移的本地检查点通过：全量 Debug、纯生产 Release 和定向 ASan 均已验证。C4c 的导入/恢复安装失败矩阵仍待完成，不能签核整个 C4 或 Frozen。

仅修改内核 DocumentRuntime 的公开边界、内部恢复安装条件及测试/中文文档，不新增生产导入命令、解析器或任何上层模块，不改变数据库和快照格式。

## 实现与迁移

公开 `attach(DocumentImage)` 已移除。原安装实现改为私有 `attachRecovered`，仅由 openImpl 在持久目录和 recover 认证后调用；安装前要求文档身份已登记、状态 Detached、归属相同，不再凭外部镜像建立新身份。对象类型/资产验证、Project/Kernel 活动准入和原恢复持久链仍保留。

C4a 已迁移 Benchmark；本次迁移剩余 11 个测试调用，不新增 friend 或测试专用恢复入口：

| 原用途 | 现在的验证 |
| --- | --- |
| 对象类型 attach | 测试模块注册普通 DocumentWrite 导入命令；两个对象中后项未知类型/版本、无效值或重复 ID，整个候选不提交；旧 Schema 原样保留，缺权限/文档 Scope 时 Handler 调用数为零，失败后对象/修订/History/活动计数不留部分提交 |
| 资产、Transient attach 负例 | 显式创建第二个空文档，然后实际执行导入命令；失败保留已创建的空身份，但其对象/修订/Journal/History 未发生业务提交，原有资产和事件断言保留；不声称 create 与 import 是一笔原子操作 |
| Project/Document 生命周期 | 新身份使用 create；项目成员测试配置真实持久化并用 open 重开；无持久化 Detached 文档确认 OpenRequiresPersistence，而不是通过镜像复活 |
| 生命周期执行保护 | 保留八种场景，原 attach 场景改为 open 内部目录写入时触发 shutdown；另一 open 场景仍从首个持久操作处探测，均确认 Kernel.ActiveExecutions 与操作完成后的 Ready |
| 停止/关闭后调用 attach | 删除不存在的方法调用，以真实编译拒绝证明 Host 无此入口；其他公开写入、读取和关闭准入负例保留，包含全量回归 |

上述类型导入是内存模式测试模块，不冒充持久提交故障验证；SQLite 资产/Transient 用例和既有恢复拒绝各按自身断言证明。C4c 继续补完整持久提交、恢复安装和失败 Host 的实际执行矩阵。

## 真实编译门禁与红转绿

新增 `architecture.host_document_compile_boundary`。每次使用独立证据目录，正常 Host create/open/snapshot 静态编译必须成功；再分别编译 attach、attachRecovered、adoptRecovered、DocumentStore.restoreDocuments，必须因对应成员的 MSVC C2039/C2248 失败。逐条检查实际错误和五个完成标记，缺头、其他语法错误、链接错误、工具链或超时不算通过。这是一个 CTest 内的五步编译检查，不是五个 CTest，也不是文本扫描。

第一轮缺少项目 `/utf-8` 编译选项，正常对照因中文头注释编码解析失败，门禁按要求失败；`build/st1c4b-compile-red.log` 保留，不把它解释为访问边界红灯。补齐 `/utf-8 /Zc:__cplusplus` 后，旧公开 attach 实际编译成功，得到真正的边界红灯：`build/st1c4b-compile-public-red.log`，退出 8、10.97 秒，正常对照已通过。

封闭入口后，12 项专项和 402 项全量均含本探针并通过。全量编译材料位于 `build/vs2022/tests/architecture-probes/host-document-compile-c1962f4b86ece872/`：healthy 为 TRUE，attach 为 C2039，其余三项为 C2248；源文件、逐项编译输出及 result.log 均保留。仅认证当前 Windows/MSVC 源码访问边界，不承诺跨工具链 ABI、同进程恶意代码隔离或链接/运行期安全。

## 后续边界

C4c 必须验证内部安装的 Opening/Open 持久写失败、运行期及启动失败后的各执行入口、可诊断材料和重试/重启行为。原实现最后一笔生命周期写失败可能保留已安装对象和 Failed 目录，本次未改变这种故障状态语义，不能因入口私有化就宣布完整回滚或全部失败安全。

C6 登记源码不兼容变更；旧调用方改用空身份 create、持久 open 和受治理事务导入，不提供兼容 attach 别名。C7 按 C4a 的种子契约重新建立容量基线。本节点本地提交，C4b/c 完整验收后再汇总推送 C4 大节点。
