## 实现

1. 接纳 Workflow/Script 时，在持有文档准入租约后核验请求 ProjectId 与文档真实所有者；不一致返回 `Workflow.ProjectMismatch` / `Script.ProjectMismatch`，不注册实例。独立未装配 DocumentRuntime 的组件保持原组件边界，不能据此绕过 AppKernel 归属检查。
2. 实例内部 RAII 在途计数覆盖完整公开 advance/cancel，包含节点回调、最终 trace/metrics、取消检查点和子任务停止控制。实例进入终态不提前释放在途所有权；异常展开正常释放。
3. 生命周期探测先用原子在途计数识别忙实例，再在实例锁下复核状态与计数。这样锁内持久化/观察回调重入关闭时，不反向等待自己的实例锁；并发状态变化不会只凭一次锁外零计数被判空闲。实例请求归属创建后不变。
4. Workflow 的 `checkpointDirty` 也是长期关闭阻塞：内存 Cancelled、持久 CancelRequested 时保持容器 Open，重试保存成功后才可关闭。重复终态查询、advance 或取消不会要求重新打开容器，也不重新执行已完成业务。
5. Document close 先封闭内存准入并探测事务/任务/编排活动，再写持久 Closing。忙时恢复内存 Open 并直接拒绝，不写 Closing/Open 往返；有效关闭仍经过原 Closing、Snapshot、Detached 路径。拒绝路径明确断言 SQL 调用数不变。
