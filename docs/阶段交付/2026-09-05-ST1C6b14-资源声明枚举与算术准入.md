# ST1C6b14 资源声明枚举与算术准入交付

## 范围与实现

本检查点只修改 Application Kernel 的 ResourceManager、CommandRegistry、既有单元测试和中文文档，不增加公共 API。契约见 [C6b14](../内核契约/ST1C6b14-资源声明枚举与算术准入.md)。

- ResourceManager 配置与仲裁按八种 ResourceKind、两种 ResourceAccess 白名单验证。
- 同一规范化资源的 Shared units 在相加前检查 `size_t` 上界，不允许回绕后绕过容量。
- 非法任务由既有调度完成链进入 Failed，保留稳定 Error，handler 不执行且不持有部分资源。
- 外部 Effect descriptor 在 Registry 入表前拒绝未知资源枚举，运行时仲裁仍保留第二道防线。
- ProjectRead/ProjectWrite 规范化、ProjectWrite 强制 Exclusive、默认容量及已声明枚举数字保持不变。

## 红灯与焦点证据

真实 Release 红灯分别保留于 `build/st1c6b14-red-tests.log` 与 `build/st1c6b14-red-resource-tests.log`。旧 CommandRegistry 接纳未知 kind/access，3 条拒绝/空表断言全部失败；旧 ResourceManager 接纳未知配置并留下槽位，未知 kind、未知 access 和 `max + 1` 聚合溢出的三个任务均执行到成功，资源用例共 32 条断言中 14 条失败。

修复后两项焦点 CTest 全部通过：外部 Effect 覆盖两类未知枚举；资源模型覆盖配置拒绝和三种异步任务失败，并逐项确认错误码与 handler 零调用。实现使用具名枚举白名单，覆盖所有未声明值，而不是只针对测试使用的 `255`。
