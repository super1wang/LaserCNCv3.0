# ST1C2a 整体准入与停止线性化

## 状态与范围

承接 C1b `80cd878`。C2a 实现、最终专项、完整 Debug、重复及纯生产门禁已通过，形成本地检查点，不是整体冻结签核。仅变更 Kernel、Gateway 和 Project/Document 生命周期准入及测试，不新增第三方库，不扩展上层模块。

契约见 [C2 统一准入与生命周期收口](../内核契约/ST1C2-统一准入与生命周期收口.md)，剩余节点见 [ST1C 计划](../内核契约/ST1C-补充审计与剩余执行计划.md)。

## 实现与旧行为差异

1. AppKernel 私有共享准入门覆盖完整公开执行调用，包括局部 Runtime 计数释放后的同步 trace/metrics 发布。Project/Document 生命周期写操作同样登记整体活动，不再被 shutdown 漏掉。
2. 同一互斥临界区内完成“检查整体活动为零并关闭准入”；调用先被接纳则停止被拒绝，停止先关闭则新请求在进入 Runtime 前被拒绝。互斥锁不跨 Handler、SQL、Schema 或模块回调持有，不串行化执行。
3. 活动事务仍优先返回 `Kernel.ActiveTransactions`；其余在途公开调用返回 `Kernel.ActiveExecutions` 并保留 Ready。各入口尚未就绪错误码保留原命名。Command/Query 门前拒绝仅复用私有观察包装，保留原失败 span、metrics 和错误上下文，不进入解析、活动登记、Handler 或状态写路径。
4. bootstrap/shutdown 排斥并发与重入，返回 `Kernel.LifecycleInProgress`；状态读取为 atomic。模块 stop 回调中再次停止不递归撤销模块，也不等待自己。
5. Workflow/Script 取消属于状态写操作，停止后拒绝；快照、Task wait/cancel 和 catalog 保留原观察/控制能力。观察和控制仍依赖 Host 存活，不表示可与析构并发。
6. 不新增公共准入开关或原始 Runtime 入口。独立组件维持原组件生命周期；内核绑定的入口使用同一个门。短期整体租约不代替文档活动、项目活动或 Scheduler 的长期资源持有。
