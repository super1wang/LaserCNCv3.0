# K10F F5 工程加固与最终版本门禁交付

## 交付结论

F5A/B/C 工程加固大节点通过，提交远端保存。Kernel 1.0 **尚未 Frozen**：最终规划 ST1 要求中的独立 Project 生命周期，与 K10B 仅规定 DocumentRuntime 的细则存在差异，仍待明确或补齐。本阶段未增加任何上层模块。

## 已完成

1. 独立 MSVC x64 ASan RelWithDebInfo 配置、健康/真实越界/真实释放后使用探针；生产目标保持无插桩。
2. 进程验证同时检查退出码和成功标记，防止“先输出成功后异常退出”被误判通过；保留开发期失败现场和测试预算修正说明。
3. AppKernel 只读公开 History、Persistence、Scheduler，合法持久化装配仅 Configuring 可用；Host 无原始写入或独立调度器生命周期入口。
4. Command/Query 注册只接受 Active/Deprecated，模块忽略注册错误也不能 initialize；四 scope 返回材料、Revision 和只读不变性有直接断言。
5. 故障夹具使用独立连接构造低层材料，不通过 const_cast、friend 或生产测试后门取得内核写权限。

主要本地检查点：`78715a3`（ASan）、`48f39a9`（退出门禁）、`68580d7`（History/Persistence 边界）、`0cbd348`（Scheduler/状态/scope）。最终生产代码与测试均固定在 `0cbd348564c5387e54bdf743b2928685a671bf13`；后续提交仅文档与生成证据。

## 未闭合与明确范围外

- **ST1 未闭合**：现有 DocumentRuntime 和 ProjectId ownership 不等于独立项目级 create/open/close。需确认补齐项目级内核生命周期，或明确本阶段仅按 K10B 文档生命周期细则验收；不能由本次测试全绿替代决定。见 [逐项审计](../内核契约/Kernel-1.0-冻结审计清单.md)。
- 本轮重复测试仅覆盖已记录的版本、参与者、轮次与同步次序；ASan 不是 TSan/LSan，也不是任意线程调度、物理断电或设备安全证明。
- 不实现 CAD、CAM、Machine、Process、Collision、Geometry/OCCT、Qt/UI、产品 CLI/RPC、脚本语言适配、AI 或动态插件。若补 Project，也只做内核状态、准入、持久化与恢复。
- 本机 `build/` 中失败日志、测试现场、数据库和二进制保留；Git 收录源码、中文记录及 21 份原始 JSON 基线，不提交本机数据库或构建二进制。
