# ST1C6c1 共享 Value 与序列化预算交付

## 交付结论

Application Kernel 已建立首批统一结构预算：`Value` 最大深度 64、最大节点 100000、对象键与字符串值累计 16 MiB、JSON/TOML 编码输入输出 64 MiB。`Schema`、JSON 和 TOML 的输入/输出均在产生可信结果前失败关闭，详细规则见 [C6c1 契约](../内核契约/ST1C6c1-共享Value与序列化预算.md)。

本节点只修改 Foundation、Infrastructure adapter、内核单元测试和中文文档，不扩展上层模块。它是 C6c 的第一个本地检查点；命令、查询、任务、编排、观察和持久 DTO 的全字段及累计预算仍归 C6c2，C6 尚未闭合。

## 实现内容

- 在公共 `value.hpp` 增加只可收紧的 `ValueBudget` 及无异常评估结果；根深度从 1 计数，节点和文本累计使用溢出安全逻辑。
- `Schema::create()` 在保存 constraints/unit 前拒绝超预算元数据。
- JSON 在解析前限制输入字节，parser 明确限制嵌套层数，DOM 转换限制节点/文本，序列化前后分别限制 Value 与编码输出；Schema backend 工作前复核材料。
- TOML 在建立 stream 前限制输入与 sourceName，DOM 转换限制结构预算，序列化前后限制 Value 与编码输出。
- JSON/TOML 共用私有转换预算和错误 details 构造，不把第三方类型暴露到 Kernel 公共头。
- 新增 9 个具名错误码，统一携带 `dimension`、`actual`、`limit`、`material`；既有语法、类型和根形状错误保持原分层。

## 红灯证据

先加入真实 Release 负例再修改生产实现：

- JSON 深度 65 序列化原先返回成功，拒绝断言失败。
- TOML 深度 65 序列化原先返回成功，拒绝断言失败。
- Schema 深度 65 constraints 原先创建成功，拒绝断言失败。

修复后增加第 64 层允许、第 65 层拒绝，以及节点、解码文本、输入字节、转义后输出字节、sourceName 和 Schema backend 前置拒绝用例。预算拒绝只返回错误，不返回部分 Value、Schema 或编码文本。
